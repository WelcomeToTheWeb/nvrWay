# P-11 — the strip shows the event's window; the clip reaches past it, and the console cannot say by how much

## Deliverable

`media.ClipBuilder` cuts a clip from the event's window **plus**
`PRE_ROLL_SECONDS` before and `POST_ROLL_SECONDS` after (S6-01), and the recorder
starts and stops on the same rule. So the footage an operator can watch is wider
than the event's `started_at`…`ended_at`, and the drawer's segment strip — which
asks `GET /api/v1/segments?camera_id=&from=&to=` for the event's own window —
draws a narrower band than the clip it sits under.

S8-06 shipped the honest version: the strip is labelled with the window the
**server echoed** (never this browser's clock) and says outright *"the clip may
reach past this window, because the server pads it by the roll settings and this
console is not told them"*. That sentence is true on every installation and useful
on none — an operator cannot tell whether the clip starts 8 s earlier or 30.

Expose the roll, in whichever of these shapes wins, and make the strip use it:

- **`GET /api/v1/settings/retention`** (or a `GET /api/v1/settings/media`)
  answering `pre_roll_seconds`/`post_roll_seconds`/`segment_seconds` — S8-08's
  SettingsPage needs the same numbers for its retention panel, so one route serves
  two cards;
- **the event view carrying the clip's own window** (`clip_from`/`clip_to`), which
  is the exact truth for one drawer and nothing else;
- **the segment request accepting a pad** — rejected in advance: it moves a
  server-side policy into a query parameter every page would have to remember.

## Exit criteria

- [ ] the choice is written here, with why the others lost, and the route is in
      `docs/api.md` and `docs/configuration.md`
- [ ] the drawer's strip spans the window the clip was cut from, and the caption
      stops apologising
- [ ] S8-08's retention panel reads the same route rather than re-declaring the
      defaults, so the console cannot show two different numbers for one setting
- [ ] `segment_seconds` comes from the same answer, so the recorder's status line
      (S4-06) and the strip agree about how long a segment is

## Verification

`docker run --rm -v $PWD/server:/src -v nvr-gomod:/go/pkg/mod -w /src golang:1.26 go test ./api -count=1 -run Settings`

`cd web && npm run test:run` — `EventDetail.test.tsx` pins the strip's window
against the server's echoed `from`/`to`; the assertion becomes the padded window
once the console is told.

## Notes

Found 2026-11-06 while building S8-06's strip. The temptation was to pad the
request by a constant the console invented — 30 s, say — which would be right on
the plan's defaults and wrong on any installation that changed them, and would
look like evidence. The strip's whole job is to say which footage exists; a band
drawn at a guessed width is worse than a narrower band that says what it is.

Related: `GET /api/v1/settings/live` (S8-04) is the precedent for this shape —
one small public settings route so the console never hard-codes a server value.
