## Why

S3-05 leaves one exit criterion unmet, and S3-08's live-sidecar run explains why:
on go2rtc 1.9.15 a config write is **durable and not live**. `POST /api/config`
rewrites the file (the manager's camera list, validated), and the new streams
stay out of `GET /api/streams` until the sidecar boots from that file. No
endpoint starts a stream at runtime, and the sidecar does not watch the file. A
restart makes the live map exactly the file the server wrote — verified.

So the plan's Step 3 criterion, "the write is visible in `GET /api/streams`
within 10 seconds", needs a restart, and the camera surface is the writer that
owns it. The manager chose the mechanism on 2026-11-02: **the server recreates
the sidecar itself** with `docker compose up -d --no-deps --force-recreate go2rtc`. That is a deliberate addition to Step 9's server shape (whose volumes are
`nvr_data:/var/lib/nvr` and nothing else), and the plan records it as an
amendment dated 2026-11-02.

## What to build

- **`server/sidecar/restart.go`** — the compose restart: the command, the timeout,
  and the post-restart probe that reports the streams the sidecar came up with.
  A disabled restarter (no compose file configured) is a first-class state,
  because dev runs go2rtc out of compose.
- The camera surface calls it **after** the config write, on every camera
  mutation, and at boot. Zone writes do not (S3-04's finding: zones are not
  go2rtc's business).
- The restart must be **health-checked, not fire-and-forget**: after the recreate,
  poll `GET /api/streams` within a budget and report which configured streams are
  live. The manager's error class is "the API is green and the stream is not
  there"; that is the report this closes.
- A restart failure keeps the camera row (the config write already landed) and
  surfaces a named error: the row is saved, the stream is not live, and the next
  write repairs it.

## Exit criteria

- [x] create, update and delete each cause exactly one restart; zone writes cause none
- [x] the restart is health-checked, and the report names the streams that came up and the ones that did not
- [x] a failed restart keeps the camera row and the config write, and names itself
- [x] the disabled state is explicit: with no compose file configured, nothing is shelled out and the console is told the stream goes live at the next boot
- [x] a real `docker compose` recreate, against a real go2rtc, makes a newly written stream live (the command's output is quoted in Notes)

## Verification command

`docker run --rm -v $PWD/server:/src -w /src golang:1.26 go test ./sidecar ./api -count=1 -v -run 'Restart'`

## Notes

The plan's §4.4 line ("the Docker socket is the one thing deliberately not
mounted") gains an exception with a narrow scope: the app may recreate **the
go2rtc service** of its own compose project. That is the price of "the write is
live within 10 seconds", and the manager paid it knowingly on 2026-11-02. The
implementation must not become a general Docker client: one command, one service,
configured by path, with the binary name configurable for tests.

What the suite pins that a reader should know:

- The command line is asserted token by token (`--no-deps`, `--force-recreate`,
  exactly one service name) — the failure it prevents is the app recreating the
  stack it lives inside.
- Order is asserted, not assumed: the restart's witness records how many config
  writes it can see behind it, because "apply then restart" and "restart then
  apply" produce identical counts and opposite deployments.
- The probe counts HTTP requests, not client calls: the client's own retries
  consume answers, and a fake that counts calls measures a fiction.
- A restart failure answers `502` with `config_applied: true`,
  `sidecar_restarted: false` and compose's own words; the row survives, the ledger
  keeps the attempt, and the next write repairs it.
- Boot recreates **only** when the live map is missing a configured camera — the
  matching case is stated as "the live map already matches the camera rows",
  because a boot that recreates the media sidecar every time drops every Live view
  that just connected.
