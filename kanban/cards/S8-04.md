The whole `./api` package is green, twice: `ok nvr/server/api 12.938s` / `12.988s`. `go vet ./...` exits 0. Tests were written first and run red — all five against `404 page not found`, because the route did not exist.

**The value is returned verbatim, and the test is built to catch a handler that helps.** `GO2RTC_PUBLIC_URL` is configured as `https://cam.example.net:1984/media` in the test — a non-default scheme, a non-default port, and a path segment, because each is a place a handler could quietly normalise. The player derives its WebSocket base with a scheme swap and a path append (`url.replace('http','ws') + '/api/ws?src='`), so a trimmed port or an added slash fails as a *media* fault in a product whose whole debugging story is that the machine says what it is doing.

**`GO2RTC_PUBLIC_URL`, not `GO2RTC_URL`.** In a real deployment these are different values: the second is the container-network address the server and worker reach go2rtc on, and it is frequently a hostname the browser has never resolved. The route answers the browser-reachable one, which is the only one the console can use.

**The gate is the plain read gate — `AuthMiddleware` alone.** That is how the camera list and the event list mount their reads, and the plan's floor is that `viewer` reads the wall. An explicit `RequireAnyRole(RoleViewer, RoleOperator, RoleAdmin)` would answer the same requests while implying a floor the rest of the read surface does not have. Unauthenticated is the middleware's own `401 {"error":"missing authorization header"}` — no new refusal words. A refresh token at the gate is refused with `401 {"error":"access token is not valid"}`, the binding convention of this API, tested here because the route is new and the convention is easy to break by accident.

**Beyond the card, because the card did not say it: an unconfigured media host is refused, not answered.** `GO2RTC_PUBLIC_URL` defaults to `http://localhost:1984` (config.go:190), so a deployment built from `config.Load` never reaches this — but a `Config` assembled without it answers `""`, and `""` travels into the player and comes back as `ws:///api/ws?src=…`: a connection error pointing at the camera, for a mistake made in an env file. The route answers `503 {"error":"GO2RTC_PUBLIC_URL is not configured, so this installation has no media host to name"}` and deliberately does **not** also send a blank `go2rtc_public_url` key, so a console cannot read the empty string as a valid host.

**Beyond the card: `server/api/handlers.go` is touched.** The route is mounted in `Register` beside the webhook surface. The card's `paths:` named only `settings.go`, which cannot mount anything by itself.

**Beyond the card: `settings.go`'s file header was wrong, and is fixed.** It read "Everything here is admin-only." That was true of the webhook half and would have led the next person to mount this route behind `admin` — which is exactly the mistake the exit criterion forbids. The header now describes two surfaces with two gates and says plainly not to read the first paragraph as covering both.

**Files beyond `paths:`** — `server/api/settings_live_test.go`, the five tests.

**Pre-existing failure, not this card's, and verified as such.** `go test ./...` fails in `nvr/server/media`: nine tests time out at 5s waiting for segment rows (`TestSegmentKindFollowsTheRecordMode`, `TestSegmentTailResetsOnRestart`, and seven more). Checked against a clean worktree at `c239e02` with none of this card's changes: the same nine fail there too, and the failing *set* differs between runs of the same tree — the signature of timing flakiness in the fake-recorder fixtures, not of a broken contract.
