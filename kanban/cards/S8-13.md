# S8-13 — CamerasPage: delete a camera (admin) with a confirmation that names the footage

## Deliverable

`DELETE /api/v1/cameras/:id` reached from the camera editor, admin-only, behind a
confirmation that states what the route is about to destroy. The server's order
is already the safe one (`server/api/cameras.go` DeleteCamera: queue the remote
purge jobs → delete the local files → delete the rows → re-render go2rtc's
config); the console's job is to make the operator read the size of that before
they cause it.

## Exit criteria

- [ ] the button renders only for a role the route answers (admin)
- [ ] the confirmation names the counts the route will destroy — segments, events,
      local files, queued remote purge jobs — from data the page already has or
      asks for, never a bare "are you sure?"
- [ ] the refusal's own sentence is what shows when the server says no (403, 500)
- [ ] a deleted camera leaves no row in the list and no editor on screen

## Verification

`cd web && npm run typecheck && npm run test:run`

## Notes

**Why this is a card and not a button.** S8-07 built the camera editor and left
delete out deliberately. Two reasons, both durable:

- It is the only destructive control in the console. `DeleteCamera` removes the
  camera's events, its segments and its **local files**, and queues jobs that
  delete the remote copies. A confirmation that does not state the size of that
  is a checkbox an operator clicks without reading, and the action cannot be
  undone.
- It needs the shell. Role gating is S8-09's; a destructive control shown to an
  operator whose role the route will refuse is worse than no control, because it
  teaches them that the console's buttons lie.

**What the confirmation must be built from.** The page has the camera row; the
counts it needs are not on it. `GET /api/v1/segments?camera_id=` answers the
segment rows and the event list answers its own count, so the confirmation can be
honest with two reads the console already knows how to make. If that is judged
too much for a dialog, the alternative is a server-side summary on the delete
path — a decision for whoever builds it, recorded here so it is made on purpose.

**Rejected — a soft "archive/deactivate" instead.** `active: false` already
exists, is already editable in the row form, and is the reversible answer to "I
am done watching this camera". Delete stays the irreversible one, and the console
should not blur the two.
