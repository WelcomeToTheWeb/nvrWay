# S5-02 — mjpeg.py: MjpegStream over requests, boundary split, cv2 decode

## Deliverable

Streaming GET on http://go2rtc:1984/api/stream.mjpeg?src=<slug>_det, boundary parsed from Content-Type, each part cv2.imdecode'd; reconnect with 5 s backoff. No cv2.VideoCapture HTTP backend.

## Exit criteria

- [x] boundary parsed from the response header, not hard-coded
- [x] socket close reconnects and the iterator resumes
- [x] timeout honored (DET_HTTP_TIMEOUT)

The three criteria, as tests:

- `test_the_boundary_is_read_from_the_response_not_assumed` runs the same two
  frames through four header shapes — `boundary=frame`, `boundary=--myboundary`,
  `boundary="quoted"`, `boundary=----WebKitFormBoundaryZzz1` — and asserts both the
  frame count and the parsed boundary each time.
  `test_the_boundary_may_be_quoted_with_a_space_after_the_semicolon` covers
  `; boundary = "frame"`, the form a hand-written server emits.
- `test_a_socket_close_reconnects_after_the_backoff_and_resumes` hands the stream a
  response that raises `ConnectionError("connection reset by peer")` after its last
  frame, then a second response, and asserts the frames arrive in order (`[7, 9]`),
  that two connections were made, and that the wait between them was exactly
  `DEFAULT_BACKOFF_SECONDS == 5.0`.
- `test_the_timeout_reaches_the_socket` asserts the opener was called with
  `timeout=3.0` — the value `__main__` reads from `DET_HTTP_TIMEOUT` — against the
  URL `http://go2rtc:1984/api/stream.mjpeg?src=porch_det`.

`test_a_body_split_at_odd_offsets_still_yields_every_frame` feeds a five-frame body
in 7-byte chunks behind a non-frame preamble, which is how a split landing inside a
JPEG and a boundary straddling a chunk get caught in the same test.

## Notes

- **The stream is infinite on purpose, and that is what the suite had to learn.**
  The first run of this suite hung: `MjpegStream.__iter__` reconnects until its stop
  event is set — correct for a camera tap, because a tap that answers nothing is a
  tap to retry, not a stream to close — so a scripted source whose responses had run
  out was treated as a dead socket and dialled forever, five seconds at a time
  (`mjpeg.py:160`, `self._sleep(self.backoff)`, found by
  `docker kill --signal=INT` on the hung container). The seam now says "that was the
  last frame": the stub opener fires the stream's own stop event when the last
  scripted body has been read (`read_stream` in `tests/conftest.py`), and every test
  injects a recording `sleep` so a backoff is asserted rather than slept. A test that
  hangs on a socket is a bug in the test.
- **The boundary is normalised, not copied.** `parse_boundary` unquotes the parameter
  and drops leading `--`, because some servers put the delimiter's dashes in the
  parameter and go2rtc does not; the delimiter is always `--` plus what is left. Both
  forms are pinned by the four-header test.
- **The endpoint is `stream.mjpeg`, not `frame.jpeg`.** `frame.jpeg` is go2rtc's
  single-frame endpoint (the console's snapshot path, S3-04); a worker pointed at it
  reads one frame and stops. The plan names `api/stream.mjpeg?src=<slug>_det` and
  `stream_url` builds exactly that, tolerating a trailing slash on `GO2RTC_URL`.
- **No `cv2.VideoCapture` anywhere in the file.** The plan forbids its HTTP backend,
  and the decode path is `cv2.imdecode(np.frombuffer(...))` on a part the module split
  itself, so a truncated part is counted (`undecodable`) rather than decoded into a
  half picture.
