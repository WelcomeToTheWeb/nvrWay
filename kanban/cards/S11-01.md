### Flake 1 — api: TestCamerasCameraWriteBroadcastsCameraStatus

The helper dialed the console socket and returned; the hub registers the client a beat *after* the handshake, so a camera write whose broadcast landed in that window reached nobody and the test waited 3 s for a frame that was never sent. Passes in isolation, flakes under load — the signature it had carried since Step 3. Fix: `watchConsole` now waits for the first `presence` frame — the hub announces presence right after `h.add`, so that frame is the proof the socket is in the client set. Evidence: 20/20 with the fix; mutation (wait for a type that never arrives) → `the console socket never announced presence: the hub did not register it` in 5.23 s, proving the wait consumes a real frame.

### Flake 2 — media: TestRunReturnsWhenLifecycleContextIsCancelled

Reproduced in the container (the run that first caught it: `timed out after 3s waiting for every child to be terminated`). Root cause is the S10-03 stranding fix: the loop's goroutine deletes its `r.runs` entry when it unwinds, and on shutdown that delete can beat `stopAll`'s snapshot of the map — `stopAll` then never sees the run and never terminates its child. The deleter orphaned the child it deleted. Fix: the deleter calls `run.stop()` after the identity-checked delete (`media/recorder.go:637`); `Stop` is idempotent on both process types (`sync.Once` on execProcess, closed-guard on the fake), so `stopAll` calling it again is free. Evidence: 100/100 with the fix; mutation (comment out only line 637) → 2/100 fail with the original timeout message; the pre-fix container run failed at the same ~2% rate.
