# S7-03 — fs.go: local dir / NFS mount with .part + rename

## Deliverable

RootPath backend: keys become nested relative paths; writes go to <key>.part then os.Rename (no partial objects on a crash); List via filepath.WalkDir.

## Exit criteria

- [x] put/get/stat/delete/list asserted against a temp dir
- [x] a crash mid-write leaves no <key> file
- [x] path confinement: a key cannot escape RootPath

## Verification

`docker run --rm -v $PWD/server:/src -v nvr-gomod:/go/pkg/mod -w /src golang:1.26 go test ./storage -count=1 -run FS`

(the seeded card's command plus the module-cache volume, which keeps the run
from re-downloading the world.)

## Notes

**Done 2026-11-04.** `server/storage/fs.go` is the `fs` driver: a `RootPath`
directory — local disk, NFS/SMB mount, or compose volume — addressed by key.
This is the backend `scripts/verify.sh` step 7 seeds (`local-tier`).

**`contract_test.go` arrives with this card.** `assertBackendContract` is the
shared list every driver is held to — put/get round-trip, stat's size and type,
replace, list under a prefix, list of an absent prefix is empty and not an
error, delete then a second delete answers `ErrNotFound`, get/stat of an object
that never existed answer `ErrNotFound`, and a zero-byte object is an object.
S7-04…S7-07 each run it against their own in-test server, so the four tiers are
held to one contract rather than to four opinions. The zero-byte case is in the
contract on purpose: a segment truncated by a crash is zero bytes, and a driver
that refuses an empty body leaves that job retrying forever against a file that
will never grow.

**A crash leaves a `.part` and never a half-written object.** The bytes go to
`<key>.part` in the destination directory, are `Sync`ed, and only then become
the object by `os.Rename` — atomic within one directory on every filesystem
this driver is meant to run on. The `fsync` is not decoration: on an NFS mount
a rename the client has not flushed can survive the client but not the power
cut. The test does not argue this, it watches: `probeReader` inspects the
directory *during* the copy (after the first 64 KiB chunk has been written) and
records that `<key>.part` exists and `<key>` does not, then fails the read.
After the failure neither name remains — the `.part` is removed on the way out,
so a directory of leftovers stays the signal for a crash rather than the normal
state of a tier.

**The size check is before the rename, not after.** The first draft checked
`written == size` after the rename and the test caught it: a refused write had
already published the object. The uploader passes the length it read from disk,
and an object that arrived short is an object the row describes wrongly forever
— so the refusal happens while the bytes are still in `.part`.

**Confinement refuses `..` rather than cleaning it away.** A key is built by
this server from a slug and a date, so a key containing `..` is a row someone
edited, and the honest answer is a refusal that names the root. Every shape it
arrives in is asserted: `../outside.mp4`, `nvr/../../outside.mp4`,
`nvr/front-door/../../../../etc/passwd`, `/../outside.mp4`, `..` — across `Get`,
`Put`, `Stat`, `Delete` *and* `List`, because a prefix is as much a path as a
key is. Two edges the test found and the driver now names:

- a key that cleans away to `.` (`nvr/..`) names the tier root, which is a
  directory, not an object — `Get` would have handed back a directory handle
  that fails on the first read, and `Put` would have renamed a file onto a
  directory. `List` of the same thing is legitimate and lists the tier.
- a leading slash is *tolerated*: the caller means the same object, and the key
  layout never produces one, so it is a caller slip rather than a different
  name.

**`Ping` answers the three things an operator can do about a mount, in three
different names.** The directory is not there → `bucket missing` (mount it, or
fix `root_path`); it is there and read-only → `bad credentials` (export it
read-write, or fix the ownership); the handle went stale →
`discovery_unreachable` (remount it). They look identical from `ls`, which is
exactly why they are three. Writability is *proved* with a probe file rather
than inferred from the mode bits — an NFS export can be read-only under 0777,
and `root_squash` turns an owner into a nobody with no warning. The mapping is
by errno (`fs.ErrNotExist`, `fs.ErrPermission`, `syscall.ESTALE`/`EIO`/
`ENOTCONN`/`EROFS`), not by message, because the message is the C library's and
moves with the locale; an error that is none of them stays itself rather than
being given a name that would send the operator to check their mount.

**`Stat`'s `ContentType` comes from the key's extension.** A filesystem has no
object metadata, and this layout always ends in `.mp4` or `.jpg` — which is a
property of the key layout (S7-07), and one of the reasons that layout is fixed
in one function. The tiers that *do* store a content type get it from the
uploader's `Put` argument.

**`List` starts the walk at the deepest directory the prefix names**, so
listing `nvr/front-door/2026/11/04/` on a year of footage is one directory read
and not a tier scan. A `.part` left by a crash is skipped — it is not an object,
and the playback proxy must never be offered one. A prefix that is not there yet
is an empty answer, not an error, because the Settings page asks before the
first recording lands.

**Objects are 0o640 in 0o750 directories**, matching the media tree: pictures of
someone's property, group-readable, world-invisible.
