# S4-01 — Recorder supervisor: one goroutine per camera, record_mode dispatch

## Deliverable

NewRecorder/Run/Close. A supervisor per camera, re-created on camera row change via a 10 s poll on cameras.updated_at. continuous = always recording; events = starts on the first signal (OpenWindow), stops POST_ROLL_SECONDS after the window closes; off = never spawns.

## Exit criteria

- [x] Close() closes open ffmpeg processes so a restart resumes recording
- [x] record_mode change on the row takes effect within one poll
- [x] OpenWindow(cameraID) is callable from signal ingest (S6-03)
- [x] every goroutine exits when the lifecycle ctx is cancelled

## Notes

Shape the card's deliverable produced, stated for the next reader:

- **The poll is the mechanism, not a notification.** `reconcile` reads `ListAll` every
  `PollInterval` (10 s default) and makes the running set match the rows: start what
  wants a recorder, stop what is gone, stop and re-create what moved
  (`slug`/`record_mode`/`active`/`updated_at`). `ListUpdatedSince` stays in the store as
  S1-10 wrote it; the recorder reads the whole table so a deleted row is seen as a
  deletion, which `updated_at >` alone cannot answer.
- **The child handle stays on the run.** A supervisor that clears its handle on the way
  out leaves the shutdown path holding nothing to terminate: that race was the first
  red test of this card, and it is the difference between "Close terminates ffmpeg"
  and a child writing into a directory its process has left.
- **`Close()` marks the recorder closed**, so no supervisor restarts a child on the way
  out, and `Run` returns only after its wait group drains — `cancel()` in main.go means
  "recording has stopped", which is what the plan's shutdown rule asks for.
- **Windows are the recorder's, not the API's.** `OpenWindow`/`CloseWindow`/`WindowEnd`
  are exported for S6-03. A signal refreshes `endsAt` by `POST_ROLL_SECONDS` (an
  `extend` is the window staying hot), the window is capped at
  `EVENT_MAX_SECONDS + POST_ROLL` so a worker that dies mid-event cannot leave a camera
  recording forever, and `OpenWindow` nudges the loop so the first seconds of an event
  are recorded before the next poll.
- **Injectability is why the suite runs in milliseconds**: clock, sleep, log, process
  factory and source command are all replaceable fields. Policy (spawn, restart,
  backoff, windows, ownership) is asserted with a fake child process in `media`; the
  real-ffmpeg suite is S4-07.
- **Boot wiring** (S1-13's "insert, don't append"): `main.go` builds the recorder after
  the go2rtc boot step and before the HTTP server, starts `Run(ctx)` on a goroutine,
  defers `Close()`, and logs what it is supervising. `api.Handlers.Recorder` carries the
  one object S6-03 will call `OpenWindow` on. The hub is nil here for the same reason
  `router.go`'s is — the live feed reaches real media at S6-04; a recorder with no hub
  records and says nothing.
