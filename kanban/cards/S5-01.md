Every pin resolves on Python 3.12 — `onnxruntime==1.31.1`,
`opencv-python-headless==5.0.0.93`, `numpy` inside `>=2.1,<3` at 2.5.4,

proves it works: `pytest tests -q -m "not slow"` reports
`122 passed, 2 deselected`.

## Notes

Host Python 3.14 has no pip/venv: every Python command runs in the detector image.
That is still true, and the image used through Step 5 is a local
`nvr-detector:dev` — `python:3.12-slim` plus the pins above plus `onnx` — so the
suite runs in seconds instead of re-downloading 300 MB per invocation. The
card-level verbatim commands were each run once against `python:3.12-slim` with a
real `pip install` (this one and S5-11's), so the pins are verified against PyPI
and not only against a pre-baked image.

- **One deviation from the card's dependency list, and it is in the dev extra
  only:** `onnx==1.17.0` joins `pytest>=8.3`. The suite synthesises a tiny ONNX
  model so `YoloOnnx` is exercised against a real `InferenceSession` rather than a
  mock, and pinning it to the version the image build exports with (S5-12) means
  the fixture model and the shipped one come from the same serialiser. The runtime
  pins are exactly the card's five.
- **`[tool.pytest.ini_options]` lives in this file on purpose**: `testpaths` and
  the marker registration are what make `pytest tests -m "not slow"` mean the same
  thing in CI and on a laptop, and an unregistered marker is a warning someone
  learns to ignore.
