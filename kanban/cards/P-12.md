# P-12 — Production server never mounted /ws: the hub was never constructed

## Deliverable

S9-03's WS-upgrade probe hit `404` on `/ws` through nginx. The fan-out is fully
built and tested (S2-10 hub, S6-08 broadcasts), but `newRouter` passed `nil` as
the hub to `api.NewHandlers` and nothing ever set `handlers.Hub` — and every
broadcast site guards with `if h.Hub == nil`, so the shipped server ran with no
live feed at all, silently. The recorder had the same nil (`media.NewRecorder(cfg,
st, nil)`), so `recorder.status` ticks were dead too. The S6-08 card's "assembler
wiring in main.go" wired the broadcast *callbacks*, not the hub construction; the
router comment deferred the hub to "S6-04", which never owned it. Fixture hubs in
the api tests and mocked sockets in the console tests meant no test ever booted
the production binary and asked for `/ws`.

Fix: `newRouter` builds the one hub per process before `Register` (the mount
point mounts `/ws` only when a hub exists at mount time): `handlers.Hub =
ws.NewHub(handlers.JWT, []string{origins})`, origins = `WS_ORIGINS` falling back
to `WEB_URL` — the console's own origin is always dialable, and an installation
that puts the console elsewhere says so explicitly. `main.go` hands the recorder
the same instance: one fan-out per process, so segment ticks and event rows
travel the socket the console reads. `server/router_test.go` (the first test in
package main) pins both facts the gap lacked.

## Exit criteria

- [x] the production router builds one hub and `/ws` is mounted: `GET /ws` without
      a token answers 401 from the hub's token gate, not 404
- [x] the recorder takes the same hub instance (main.go), so recorder.status ticks
      reach the live feed
- [x] a package-main test pins both, so the gap cannot silently return
- [x] full Go suite green, vet clean
