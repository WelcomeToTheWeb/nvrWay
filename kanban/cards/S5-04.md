# S5-04 — tracker.py: greedy IoU tracker (>=0.30, 6-frame expiry)

## Deliverable

Best-first IoU matching; unmatched detections spawn tracks; tracks expire after 6 frames; ids monotonic per camera.

## Exit criteria

- [x] 5 synthetic frames keep one stable track_id
- [x] occlusion gap <= 6 frames resumes the same id; > 6 spawns a new one

## Verification

`cd detector && python3 -m pytest tests/test_tracker.py -q`

**Observed** 2026-11-03, in `nvr-detector:dev`: `9 passed in 0.02s`.

- `test_a_slowly_moving_person_keeps_one_id_for_five_frames` — four pixels a frame,
  one id across all five, `hits == 5`.
- `test_a_detection_that_flickers_for_six_frames_resumes_the_same_id` — the gap is
  walked frame by frame, asserting the track is still live and ages exactly one frame
  per frame, then the detection returns and the id is the original with `missed == 0`.
- `test_a_detection_that_flickers_for_seven_frames_starts_a_new_id` — `live == 0` once
  the grace window runs out, and the new id is greater than the old one (ids are
  monotonic per camera and never reused, which `test_ids_do_not_repeat_within_a_camera_
  even_across_lifetimes` checks over four lifetimes).
- `test_two_tracks_that_cross_keep_their_ids` is the one that justifies "best-first".
  A at `(0,0,100,100)` and B at `(40,0,140,100)` overlap each other at IoU 0.43, so a
  matcher that walks detections in arrival order hands A the box that belongs to B and
  the two people trade identities mid-crossing. Matching the best pair first —
  `(d1,B)` and `(d2,A)`, both IoU 1.0 — keeps each id on its own trajectory, and the
  test asserts the id→box mapping, not just the id count.
- `IOU_THRESHOLD == 0.30` and `MAX_AGE_FRAMES == 6` are asserted as constants.

## Notes

The loiter rule is per track_id, so tracker stability is the loiter contract.

- **A spawned track was being aged on the frame it was born on.** The suite caught it
  on the first expiry test: after one empty frame the track reported `missed = 2`. The
  missed-loop keyed only on "not matched this frame", and a track created this frame is
  neither matched nor missed — so every track expired a frame early and the plan's
  six-frame gap was really five. The loop now also skips a track whose `last_frame` is
  the current frame, and the test asserts the age frame by frame so the off-by-one
  cannot come back in either direction.
- **A track inside its grace window is returned to the caller.** `update` answers every
  live track — matched, newly spawned, and still inside the window — because a person
  behind a doorframe is still the person the zone rule is about, and the event's own
  idle close (10 s) is what decides whether the run ended. Dropping them at expiry
  instead would make the tracker, not the state machine, the thing that ends events.
- **One detection has one owner.** The matched-set guard means a second track cannot
  claim the box that was already absorbed, which is what would otherwise split one
  person into two ids when two tracks overlap.
