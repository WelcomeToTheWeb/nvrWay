# S2-10 — ws/hub.go: local hub, token auth, origin guard, the seven message types

## Deliverable

## Exit criteria

- [x] bad token closes the socket; foreign origin is rejected
- [x] envelope shape and type names are exact (the console switches on them)
- [x] fan-out reaches every connected client
- [x] one mutation handler broadcasts exactly one type

## Notes

Single instance: no Redis, the hub is local (plan decision 8).

`server/ws/hub.go` (the whole package). The tests are filed under S2-11's path
(`server/ws/hub_test.go`), matching how the Step 2 suites card is seeded.

Decisions recorded here because they are decisions:

- **The gate is at the handshake, not in the socket.** A bad token answers 401 and
  a foreign origin 403 *before* the upgrade, so the console's `onclose` fires with
  no feed at all; a refresh token is refused at the same gate as a bad one. The
  origin allowlist is the hub's own (WS_ORIGINS ∪ WEB_URL, normalised to
  scheme://host, case-insensitive, trailing path ignored) with nhooyr's built-in
  check switched off, because that check compares Origin with RemoteAddr — behind
  the proxy that is the proxy, and it cannot express an allowlist.
- **No Origin header is accepted, the token decides.** That header is what a
  browser adds and a CLI, curl, or a worker does not: refusing it would refuse
  every non-browser client for a protection a browser cannot bypass anyway.
- **The read pump runs on the handler goroutine.** The response is already
  upgraded when the pumps start; a handler that returns hands the connection back
  to net/http, cancels the request context, and the socket dies. That is how a
  live feed gets a console that disconnects the moment it connects.
- **`Conn.Close` is never paid for on the broadcast path.** nhooyr's Close waits
  for the peer's echo, up to five seconds. A queue-full drop therefore unregisters
  the client synchronously and closes the socket on its own goroutine — a
  signal-intake handler that POSTs an event and broadcasts must not stall five
  seconds per dead console. `Broadcast` is measured in the test: 20 frames with a
  client that is not reading, and it returns in milliseconds.
- **A client's send channel is never closed.** Broadcast snapshots the client set
  and hands frames after that; a client dropped in the window is a send on a
  closed channel, i.e. a panic in the handler. The gate is a `closed` flag under
  the client's own lock, taken by every sender.
- **`ts` is the server clock, injected.** `NewHubWithClock` takes the clock, so a
  test asserts the exact timestamp; the field is not assignable after
  construction, because broadcasts read it from other goroutines.
- **Presence is the hub's own business**: announced on connect and on departure,
  with the count. The seven handlers each broadcast exactly one type, and
  `Broadcast` refuses a type the console has no case for, so an invented type
  fails at the call site.
