## Notes

**Done 2026-11-04.** `server/storage/keys.go` is the layout, in one exported
function — `KeyFor(ObjectRef) (string, error)` — and it is the only place a key
is ever built. The uploader, the sweeper, the playback proxy and an operator
restoring with `aws s3 cp --recursive` all agree on where a file is without any
of them coordinating, because there is one function that says so.

**The layout, verbatim:**

```
segment    nvr/<camera_slug>/<YYYY>/<MM>/<DD>/<basename>.mp4
clip       nvr/events/<event_id>/clip.mp4
snapshot   nvr/events/<event_id>/snapshot.jpg
```

**`<basename>` is the local file name, and that one choice is what makes a
restore a copy rather than a translation.** The segment rows already point at
that name, so downloading the tree back into `SEGMENTS_DIR` gives the manifest
the files it already names — `TestKeyLayoutIsStableAcrossRestarts` asserts the
base name of the key equals the base name of the local file, which is the
round-trip in the only form that matters. It also means the name is unique across
cameras without a counter, because the recorder's own name is
`<slug>-<generation>-<n>.mp4` and starts with the slug.

**The same file under two different `SEGMENTS_DIR`s produces the same key.** The
directory the recorder writes into is not part of the layout, so moving the
volume does not orphan a bucket.

**The date path is UTC, and the reason is a DST fall-back.** A server in a zone
with a change would otherwise put the repeated hour into two different
directories, and an installation that changes its `TZ` would split one day of
footage across two paths — both of which read as lost footage to someone browsing
the bucket. The row's `start_ts` is already UTC, so this is the same number the
timeline shows, formatted for a path. `TestKeyLayoutDatesInUTC` builds a ref from
the same instant expressed in `UTC-5` and asserts the key still says the 4th.

**`keyRoot` is not the row's `prefix`, and both are applied.** `nvr/` is what
this installation calls its own; `prefix` is where on the tier this backend keeps
its things. A bucket with no prefix holds `nvr/…` at its top, a bucket shared
with another service holds `media/nvr/…`. Conflating them is how a shared bucket
ends up with two installations' footage indistinguishable.

**Event object names are fixed, not derived.** An event's clip is always
`clip.mp4` whoever built it and whatever temp file the builder renamed, which is
what lets the playback proxy answer `/api/events/:id/clip` without consulting the
tier for a name.

**Three refusals, each naming what is wrong.** A slug that fails
`models.ValidSlug` (the same rule that makes it a go2rtc stream name and a file
prefix, so a slug that reaches the tier is already validated and this is the
belt); a segment whose file name is not an mp4 — the recorder only writes mp4, so
a manifest that says otherwise disagrees with the file, and uploading it would
give the playback proxy an object it answers with the wrong type; and an event id
that is not a safe single path segment. The id check is deliberately **not** a
UUID parse: ids are UUIDs in practice, and the check that has to survive is the
one against a row someone edited by hand, which is "no separators, no dot-dot, no
NUL, not absurdly long" regardless of what the id is spelled with.

**The layout checks itself.** `KeyFor` refuses a key that does not start with
`nvr/` or that contains `..`. Every driver refuses a `..` in a key too, but a
layout that produced one is a bug in this file, and checking here names the bug
where it is made rather than at the tier.

**The four-driver assertion checks the destination, not a round trip.**
`TestKeyLayoutOnEveryDriver` runs the three object kinds through fs, s3, webdav
and sftp and asserts where each object *landed*: `os.Stat` of root + key for the
two drivers whose tier is a real filesystem, and the request line the tier
actually saw for s3 (`/nvr-media/nvr/…`) and WebDAV (`PUT /media/nvr/…`). A key
that round-trips through a driver's own path handling but lands somewhere else is
still a broken layout, and that is the failure mode this guards.

**One expectation corrected on the way:** `filepath.Base("/var/lib/nvr/segments/")`
is `"segments"`, not `""` — Go's `Base` strips trailing slashes — so a path that
names a directory rather than a file is caught by the extension check, not the
empty-name one. Both refuse it; the test now pins which message an operator
reads, and the empty-`LocalPath` case is what reaches "no file name".

**Two properties an operator browsing a bucket depends on are asserted, not
assumed:** zero-padded months and days (or a bucket browser sorts August after
December — `January is 01` pins it), and keys that sort in time order at a fixed
shallow depth with room to spare under a tier's key limit.
