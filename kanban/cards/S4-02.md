## Notes

Decisions the card's criteria forced, recorded for the next reader:

- **The generation is the spawn counter, and the segment number continues across
  generations.** A spawn reads `recorder_gen_<camera_id>` (0 when absent), reads the
  last number written in that generation from the manifest
  (`SegmentStore.MaxSegmentNumber` — S1-10 wrote it for exactly this), then advances
  and persists the generation. So generation 1 writes `porch-1-0…5`, a restart writes
  `porch-2-6…`: ffmpeg's own numbering restarts at 0 and would overwrite, and the
  pair (generation, continued number) is what makes every file name unique.
- **Persisted before the child starts.** A spawn that fails to start still advances
  the counter. TestRecorderGenerationIsPersistedBeforeTheChildStarts pins the order,
  because the alternative is a next spawn reading the old generation and writing over
  the files the last generation produced.
- **An unreadable counter refuses to spawn.** `settings.GetInt`'s rule — an
  unparseable value is an error, not zero — is honoured: a recorder that invents a
  generation starts numbering over and overwrites footage, which is the one thing the
  counter exists to prevent. The log line says which key to repair.
- **`-c copy` lives in the source arguments, not the fixed tail.** The plan lists it
  after `-i`, and the source is the part a suite overrides (S4-07's lavfi hook), so
  `SourceCommand` returns `-rtsp_transport tcp -i … -c copy` and the segment flags are
  the recorder's own. The suite asserts the whole argv against the plan's line, so
  moving `-c copy` would fail a test.
- **No ffmpeg on the host** (S4-02's note): these tests use the fake process factory.
  Real ffmpeg is S4-07, in the image that carries it.
