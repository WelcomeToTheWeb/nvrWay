Vitest wiring loads rather than dangling: `npx vitest run --passWithNoTests` exits 0 with `include: src/**/*.test.{ts,tsx}` and no error for the `setupFiles` entry — the suite itself is S8-11.

**Files beyond the card's `paths:`.** Four were needed to make the declared deliverable true, and one was named by the plan:

- `web/package-lock.json` — the exit criterion is `npm ci`, and `npm ci` refuses to run without a lockfile. A scaffold with an unpinned tree is not reproducible.
- `web/tsconfig.node.json` — `tsconfig.json` carries `references: [{path: "./tsconfig.node.json"}]`, and the plan names the file in the copy list.
- `web/src/main.tsx` — `index.html` names `/src/main.tsx` as the module entry. A scaffold whose entry does not exist is a config file, not a console: `vite build` would fail on it. It renders a placeholder that says it is a placeholder; S8-09 replaces it with the router.
- `web/src/index.css` — `index.html`'s body classes (`bg-bg text-text-primary font-sans`) and `tailwind.config.ts`'s colour roles resolve to CSS custom properties. With no definitions the bridge points at nothing and the console renders unstyled. This file defines them, night as the default rendition.
- `web/src/vite-env.d.ts` — Vite's client types, so `import.meta.env` is typed when the pages arrive.

**Deviation — tailwind colour roles are nvrWay's, not OurWay's.** The plan says to copy the file; copying it verbatim would have brought an RMM's vocabulary into an NVR — `ink`/`ink-plate`/`ink-on-plate`, `stamp`, `service`, `due`. The structure is kept (letterpress radii, `cap`/`stamp` letterspacing, colour named by meaning not hue); the roles are the ones this product has: `bg`, `text`, `rule`, `status` (a camera's truth, from `camera.status`), `severity` 1–5 (the plan's scale, 3 = call somebody), and `accent` mapped to `var(--accent)` — the token the plan's zone-editor rule names for the 20 % polygon fill — rather than OurWay's `var(--service)`.

**Deviation — no webfonts vendored.** OurWay self-hosts Barlow / Archivo Narrow / JetBrains Mono from `src/assets/fonts` (OFL). The font stacks keep those names and fall back to `ui-sans-serif` / `ui-monospace`, so the console renders in the system UI font until someone vendors the faces. Vendoring is then a change to `fontFamily` plus a `fonts.css`, never to a component. Adding ~1 MB of binaries was not this card's call.

**Host drift, worth recording.** The card's old note said "Node 22 + npm 9 exist on the host". The host is Node **v26.13.0** and npm **11.20.0**. Two consequences, both verified here:

- npm 11 gates install scripts. `npm ci` prints `install-scripts: esbuild@0.21.5 (postinstall: node install.js)` as not covered by allowScripts, and does not run it. The build still works — the platform binary arrives as the `@esbuild/linux-x64` optional dependency, so the postinstall is a verification step, not the delivery mechanism. Do not "fix" the warning by approving the script; nothing is broken, and CI (npm on ubuntu-latest) sees the same tree.
- `vite preview` binds `[::1]` only by default (`ss -ltnp` → `LISTEN … [::1]:3113`; `curl http://localhost:3113/` → 200, `curl http://127.0.0.1:3113/` → 000). This harness passed `--host 127.0.0.1`. **`scripts/e2e-stack.sh` (Step 9/10) must either pass `--host` or reach the preview over `localhost`, not `127.0.0.1`** — otherwise the Playwright suite cannot connect and the failure will look like a broken console.
