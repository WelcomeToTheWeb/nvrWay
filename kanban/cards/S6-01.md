# S6-01 — clips.go: windowed concat with padding + the empty-window rule

## Deliverable

On close (and at write time for the open case) schedule assembly POST_ROLL_SECONDS after EndedAt: window [StartedAt - PRE_ROLL, EndedAt + POST_ROLL], segments from the table, ffmpeg concat -c copy -movflags +faststart.

## Exit criteria

- [x] no overlapping segments -> clip_key="", ClipSeconds=0, log 'clip skipped: no segments for window', event stays visible with its snapshot
- [x] ClipSeconds = min(window, sum(segment seconds))
- [x] a measured clip under 2 s is padded by repeating the last segment once
- [x] ffprobe-measured duration within +/-1.5 s of the requested window
- [x] time.AfterFunc per open event, cancelled on close

## Verification

`docker run --rm -v $PWD/server:/src -w /src golang:1.26 go test ./media -count=1 -run Clip`

`docker run --rm -v $PWD/server:/src -w /src golang:1.26-ffmpeg sh -c 'command -v ffmpeg ffprobe && go test ./media -count=1 -run Clip -v'`

`docker run --rm -v $PWD/server:/src -w /src golang:1.26 go test ./api -count=1 -run Clip`
(the signal path's half: the route arms the assembler)

## Notes

**Done 2026-11-04.** `server/media/clips.go` is `media.ClipBuilder`: the window
is `[started_at - PRE_ROLL_SECONDS, ended_at + POST_ROLL_SECONDS]`, the footage
comes from `Segments.ListRange` (overlapping, **any** `kind`, ordered by
`start_ts` — the row is the manifest, a file with no row is not footage), the
command is the plan's line verbatim
(`ffmpeg -y -f concat -safe 0 -i <list> -c copy -movflags +faststart <CLIPS_DIR>/<event_id>.mp4`,
list written as `file '<abs path>'` lines into `CLIPS_DIR/<event_id>-concat.txt`
and removed after), and every outcome except a command failure is filed on the
row.

Each exit criterion and the test that holds it:

| Criterion | Test |
| --- | --- |
| empty window → `clip_key=""`, `ClipSeconds=0`, the log line, snapshot intact | `TestClipAbsentWindowLeavesTheEventWithItsSnapshot` |
| `ClipSeconds = min(window, sum)` | `TestClipSecondsIsTheWindowClampedByTheFootage` (both directions: 10 s window over 15 s footage → 10; 30 s window over 3 s footage → 3) |
| under 2 s → last segment repeated once | `TestClipUnderTwoSecondsIsPaddedByRepeatingTheLastSegment` (fake probe 1.00 → 2.40) and `TestClipRealShortClipIsPaddedToPlayableLength` (real ffmpeg: 1.00 s → 2.00 s) |
| ffprobe within ±1.5 s of the window | `TestClipMeasuredDurationMatchesTheWindow` — real 3×5 s segments, `window 15.00s, footage 15.00s, clip 15.00s, ffprobe 15.00s` |
| `time.AfterFunc` per open event, cancelled on close | `TestClipAssemblyIsArmedAtPostRollAndCancelledOnClose`, `TestClipOpenEventArmsOneTimerNotOnePerExtend`, `TestClipTimerFiringAssemblesTheClip` |

Four decisions the card left open, decided here:

1. **The open case's deadline is the ceiling.** The plan arms "at event-row
   write time for the open case" and cancels "on close". An open event is armed
   at `started_at + EVENT_MAX_SECONDS + POST_ROLL_SECONDS`: an open event cannot
   outlive `EVENT_MAX_SECONDS`, so that is the only clip an event whose worker
   died without a close will ever get. Extends do **not** re-arm it (one timer
   per open event, not one per signal); the close `Stop()`s it and arms
   `ended_at + POST_ROLL_SECONDS`. A delay already spent clamps to 0, so an event
   closed while the server was down is assembled now.
2. **`-c copy` cannot cut mid-GOP, so the clip is the whole segments the window
   touches.** The plan's command copies rather than re-encodes, so a window that
   starts mid-segment starts at that segment's start. Measured, not assumed:
   `TestClipWindowStartingMidSegmentKeepsWholeSegments` — a 10.00 s window over
   three 5 s segments gives `clip 10.00s, ffprobe 15.00s`. The row states the
   window the event asked for; the file states the footage. That is why the
   ±1.5 s criterion is asserted against a window aligned to segment boundaries.
3. **`ClipSeconds` is the plan's arithmetic, not the ffprobe measurement.**
   `min(window, Σ selected segment seconds)`, and the padded repeat does not
   lengthen it (the repeat lengthens the file, not the event). The ffprobe number
   is logged beside it — `window 15.00s, footage 15.00s, clip 15.00s, ffprobe
   15.00s` — so an operator can see both, and a failed probe costs the number and
   not the clip (`TestClipProbeFailureStillFilesTheClip`).
4. **Rows whose local file is gone are skipped, counted.** The sweeper sets
   `local_deleted_at` and keeps the row; a file can also vanish a tick later.
   ffmpeg's concat demuxer fails the *whole* clip on one missing file, so
   `selectReadable` drops those rows and the clip is cut from the footage that is
   here (`TestClipSkipsRowsWhoseLocalFileIsGone`).

**The card's paths list grew: an unhooked builder is dead code.** The signal path
schedules onto it (`api/detector_api.go`, after the signal is applied and the
recorder's window is opened), `Handlers.Clips` is a `ClipScheduler` interface
(`Schedule`/`Cancel`) so the api suite asserts the call with a spy rather than an
ffmpeg run, and `main.go` starts it in the plan's boot order — after the recorder
whose footage it cuts, before the API that reports what it produced. A refused
signal arms nothing: the event did not move, so the deadline did not
(`TestClipAssemblyIsNotArmedForARefusedSignal`).

**Reconcile covers what the signal path cannot see.** `Run` polls every
`DefaultClipReconcileInterval` (15 s): every open event (`ListOpen`, the plan's
restart story) and every closed event inside `MissedEventLookback` (24 h, bounded
by the event list's own 200-row page) that has no clip. An event this process
already attempted is not re-armed, so a tick is a query and not a fan-out
(`TestClipReconcileAfterARestartArmsOpenAndMissedEvents`,
`TestClipAbsentEventIsNotReArmedByEveryTick`).

**Left to other cards, so the next reader does not look for it here:** the upload
job for a finished clip (S7-08), `Cancel` on `DELETE /api/v1/events/:id` (S6-04),
the WS fan-out that tells the console a clip landed (S6-08), and the prose in
`docs/architecture.md`'s "Clip flow" section (S9-10 — the skeleton names the
empty-window rule; the literals it needs are the log line
`clip skipped: no segments for window`, `clip_key == ""`, `clip_seconds = 0`, and
that a `record_mode=off` camera therefore produces snapshot-only events, which is
intended).
