# P-06 — Mirror the cards into the pi-kanban board's task store (kanban/pi_board.py)

## Deliverable

The pi-kanban board (the dev tool, not this repo's board) shows its own task list, which was empty while this board carried 111 cards: pi-kanban reads task JSON from ~/.pi/agent/kanban/tasks/<list>/<id>.json and nothing wrote it. kanban/pi_board.py mirrors these cards into that store so the tool's board shows this project's real state — cards stay the source of truth, the mirror is derived and disposable, and --check proves the mirror matches the cards.

## Exit criteria

- [x] one task file per card, carrying the fields pi-kanban parses (id, subject, description, activeForm, status, blocks, blockedBy)
- [x] task ids are numeric and stable (step + card number), so the board's numeric sort lists cards the way KANBAN.md does
- [x] the five columns collapse onto the board's three states without losing the Blocked reason — it is quoted in the task description
- [x] --check reports drift (wrong status, missing task, ghost task) and exits non-zero
- [x] re-running the mirror rewrites nothing when nothing changed and deletes tasks whose card is gone
- [x] the suite runs on stdlib alone (host Python 3.14 has no pip)
- [x] pre-commit regenerates the mirror, so the tool's board cannot lag the cards
- [x] the mirror writes only into the board's task store — never into kanban/cards/

## Verification

`python3 kanban/test_pi_board.py && python3 kanban/pi_board.py && python3 kanban/pi_board.py --check && pi-kanban task list --all`

## Notes

Found 2026-11-02: the board said 'no active tasks' with 111 cards in kanban/cards/. pi-kanban's task store (server.js: TASKS_DIR = <agent dir>/kanban/tasks, one JSON per task; lib/task-store.js normalizeTask defines the fields) is a separate board from KANBAN.md and nothing in this repo wrote it. Its statuses are only pending | in_progress | completed, and its task list sorts by parseInt(id, 10) — so card ids like S2-04 need a numeric id.

Test-first: kanban/test_pi_board.py was written and run before the module existed — `ModuleNotFoundError: No module named 'pi_board'`. Four of its first assertions were the tests being wrong, not the mirror: sync returns the count of files it changed (0 on a clean re-run, not the card count); the sample omitted S1-07/S1-12 so S2-04's blockedBy is legitimately empty; a hand-written task file drifts on every field, not just the one under test; and register_sessions must create the list's task dir, because the board's getCustomTaskDir() ignores a shared list whose directory is absent. Fixed the assertions, kept the mirror's semantics.

Observed 2026-11-02 (host Python 3.14.4, no pip — stdlib unittest):

    $ python3 kanban/test_pi_board.py
    Ran 22 tests in 0.032s
    OK

    $ python3 kanban/pi_board.py

    sessions registered in /root/.pi/agent/kanban/agent-activity/_task-maps/nvrway.json: 01a19986-10e0-72de-93ff-ac6cd9214cd2

    $ python3 kanban/pi_board.py --check
    112 cards, 0 drift(s) in /root/.pi/agent/kanban/tasks/nvrway          # exit 0

    $ pi-kanban task list --all --json | <count by status>

112 tasks for 112 cards; 84 pending = 83 Backlog + 1 Blocked (S9-06 names its blocker in the task description); 2 in_progress = S2-04 and this card (Review counts as in_progress: the tool has no Review column); 26 completed = the 26 Done cards. The one changed file was this card's own task after its column moved — a clean re-run changes 0, and sync deletes a task whose card is gone (test_sync_removes_tasks_for_cards_that_are_gone).

Mirror only: writes <agent dir>/kanban/tasks/nvrway/ and the board's _task-maps/nvrway.json. Nothing in kanban/cards/ is touched, and cards stay the source of truth. `kanban/pre-commit.sh` runs the mirror after regenerating KANBAN.md, and skips quietly on a machine with no board installed.
