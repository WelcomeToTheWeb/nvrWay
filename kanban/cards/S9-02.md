## Observed

**Observed** 2026-11-06 — `docker build -f docker/Dockerfile.detector -t
nvr-detector:s902 .`: exit 0. Inside the image, with `testdata/` mounted at
`/testdata`: `python -m pytest tests/test_model_smoke.py -m slow -q` → **2
passed**. In-image model hash `d23c126273b9083b5f60b1e77a3183713c9415dee43ff4d7e62f7a4f22ff506e`
— exactly the `exported[]` hash recorded in `testdata/fixtures.json` (2026-11-03).
`docker exec id` → `uid=999(nvr)`.

The offline criterion, read honestly: BuildKit keys RUN cache on the network mode,
so a literal `--network=none` build re-runs every pip layer and can never succeed
for any Dockerfile that pip-installs. What the criterion means — and what was
proven — is that **stage 2 rebuilds without stage 1's network work**: after a real
content change in `detector/`, a `--target runtime` rebuild showed all five export
steps (torch install, apt libs, model download, ONNX export) **CACHED**, and only
stage 2's `COPY detector/ ./` + `pip install -e .` re-ran. The other half — stage 1
needs network and says so loudly — was shown by `--network=none`: the build dies
at stage 1's first RUN with `No matching distribution found for
ultralytics==8.4.195`. Named the runtime stage `AS runtime` so `--target` can
address it; that is the only edit to the Dockerfile.

Mutation evidence — each break kills its criterion, restore re-green (`diff` clean):
