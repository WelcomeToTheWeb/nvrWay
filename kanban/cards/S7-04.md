## Notes

**Done 2026-11-04.** `server/storage/s3.go` is the minio-go driver: endpoint,
region, bucket and prefix from the row, `Secure = !InsecureTLS`,
`BucketLookup: minio.BucketLookupPath` unconditionally, credentials unsealed by
`Open` (S7-01).

**Path style is asserted on the wire, not in the options struct.** The test
server records every request URI and `Host`, and fails if any host begins with
`nvr-media.` (virtual style) or if no request carried the bucket in its path.
Virtual-host style needs a wildcard DNS record and a certificate covering it —
which is exactly what a media tier on a LAN does not have — and the plan's list
of targets (MinIO, R2, B2, Wasabi, self-hosted) is the list that works
path-style.

**`EnableSSL = !InsecureTLS` is asserted from both sides.** With the box ticked,
`Ping` against a plain-HTTP tier *succeeds* — a client configured for TLS would
fail its handshake, so an answer can only come from `EnableSSL` being false.
With it unticked, the driver is pointed at an `httptest` TLS server with a
certificate this process does not trust, and the failure must read as a TLS
failure (`x509`/`certificate`) *and* map to `discovery_unreachable`. That second
half caught a real flaw in the first draft: the unreachable branch wrapped only
the sentinel and dropped the cause, so the operator got `discovery_unreachable`
with no idea it was a certificate. The message now carries the underlying error
while the name stays the one the console draws.

**`Get` answers a missing object at `Get`, not at the first `Read`.** minio's
`GetObject` returns a handle whose error surfaces on the first read, and by then
the clip route has written its 200 headers — the operator would get a truncated
download that plays as silence instead of the named 404. So `Get` stats the
handle and closes it if it is not there. One extra HEAD per playback request is
the price, and `TestS3GetAnswersAtGetNotAtRead` asserts the reader is nil
alongside the error.

**`Delete` of an absent object is silent, and that is the protocol's answer.**
S3's DELETE is idempotent. The shared contract (S7-03) originally required a
second delete to answer `ErrNotFound`, which is a filesystem's semantics; the
contract now asserts only that the object is gone afterwards, and each driver
states its own second-delete behaviour. The sweeper clears the row's
`remote_key` either way, which is why the contract does not pick one.

**The in-test tier is the real protocol, with one gap stated.** `gofakes3` over
`httptest`, driven by minio-go's own HTTP client — not a mock of the driver.
Two gaps are recorded rather than papered over:

- **gofakes3 does not verify signatures**, so the suite wraps it in a middleware
  that answers 403 `AccessDenied` for an access key it does not recognise —
  which is what MinIO's first refusal looks like, and what proves the unsealed
  credential actually travels. The secret half (`SignatureDoesNotMatch`) is
  asserted where it is decided, in `TestS3MapErr…` and in the driver's own
  mapping test. Recomputing minio-go's signature server-side turned out not to
  be available: `signer.SignV4` **overwrites `X-Amz-Date`** with the current
  time, so a received signature cannot be reproduced with it, and uploads over
  plain HTTP use the streaming scheme anyway. That is written down in
  `s3IsStreamingPayload`'s comment for the next person who tries.
- **gofakes3 refuses a PUT with no `Content-Length`** (`MissingContentLength`,
  `gofakes3.go:701`) and minio-go sends a zero-length body chunked, so the
  contract's "a zero-byte object is an object" case **skips on this driver** —
  the contract's first skip, taken with the reason on the card. Real S3 and
  MinIO accept it.

**An endpoint that carries a path is refused, not normalised.** A browser URL
pasted into the field is the common mistake, and path style puts the bucket in
the path, so a path there would be sent twice. A scheme is stripped and is
decoration: `insecure_tls` decides TLS, one rule, no exceptions — otherwise
`http://host` with the box unticked is a contradiction with two possible
meanings.

**A 503 keeps its own name.** `mapErr` maps by S3 code and HTTP status, and an
unrecognised code keeps the server's code in the message and maps to `""`.
Inventing `discovery_unreachable` for a sick MinIO would send the operator to
check their network. The four names are matched first, in the order S7-01 fixed:
`NoSuchBucket` → bucket missing, an object 404 → `ErrNotFound` (not one of the
four — the caller answers its own named 404), 401/403 and the credential codes →
bad credentials, and a zero-valued `ErrorResponse` (no S3 document at all) →
unreachable.

**No secret in any log line, asserted on the log.** The test redirects the
standard logger, runs a failing connection test, and looks for the secret in
both the buffer and the returned error. The access key may legitimately appear —
it is the server that names it, in its message, and it is not a secret in the
sense the seal is about.

**`MaxRetries: 2`, not minio's default ten.** Ten is right for a transfer and
wrong for a connection test: the Settings page asked a question and the answer is
"nothing answered", not a thirty-second spinner. The uploader's backoff (S7-08)
is the retry that matters.
