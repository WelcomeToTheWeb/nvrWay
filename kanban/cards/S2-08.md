**Decisions, with the reason.**

- **Two gates, not one.** `RequireRole` gates on a role name; `RequirePermission`
  gates on a permission read from the **role rows** (via `Claims.Grants` +
  `PermissionsGrant`), so a token naming a role the installation does not have
  grants nothing, and an operator's edit to a role takes effect at the next
  issue. Route refusals record `insufficient role` for both, because the console
  has one state for "you may not do this".
- **The rate budget caps at the burst, not at the minute.** A token bucket that
  refills to `RATE_LIMIT_PER_MINUTE` lets an idle console spend a whole minute's
  requests in the first second after a quiet period; the cap is the burst, which
  is what the config comment says the burst is. `burst=0` → `perMinute/10`,
  floor 1 (config.go resolves 0 the same way, so a limiter built from an unset
  config behaves like the server's).
- **Empty `WORKER_TOKEN` is 403, not 401.** A 401 tells the worker "your token is
  wrong"; the truth is "the internal API is switched off", which is the
  operator's setting, not the worker's.
- **Denials are keyed on the matched route** (`GET /api/users/:id`), not the
  request path, so the ledger groups refusals by act; the `:id` the request
  carried goes into `target_id`. An unregistered route records `route.denied` — a
  new route group that never declared its verb is visible as one.
- **A gate that cannot read the role table answers 503.** `RequirePermission`
  does not fall through permissively when `ListRoles` fails.
