# S9-05 — docker-compose.prod.yml: image-based, no builds, GO2RTC_PUBLIC_URL required

## Deliverable

Same services with `image: ghcr.io/welcometotheweb/nvr/{server,web,detector}:latest`,
no build sections, no MinIO, `GO2RTC_PUBLIC_URL` required, OurWay's tag
semantics and comments.

## Exit criteria

- [x] config validates without a build context
- [x] missing GO2RTC_PUBLIC_URL fails with a message naming the variable

## Verification

`docker compose -f docker-compose.prod.yml config -q`

## Observed

**Observed** 2026-11-06 — `docker compose -f docker-compose.prod.yml config -q`
with the root `.env` (gitignored) filled: exit 0, zero `build:` lines. Missing
`GO2RTC_PUBLIC_URL`: `error while interpolating
services.server.environment.GO2RTC_PUBLIC_URL: required variable
GO2RTC_PUBLIC_URL is missing a value: GO2RTC_PUBLIC_URL is required in
production: it is the origin the browser dials for live view`. Live: images
retagged to the ghcr names, `up -d` → all five `(healthy)`; console :3000
`root=200 login=200`.

The file's own decisions beyond the skeleton:

- **Secrets have no dev defaults.** `POSTGRES_PASSWORD`, `JWT_SECRET`,
  `WORKER_TOKEN`, `GO2RTC_USERNAME/PASSWORD`, `GO2RTC_PUBLIC_URL` are
  `${VAR:?message}` gates — compose refuses to resolve, naming the variable.
  (YAML note: a `:?` message containing `: ` must be double-quoted or the
  scanner dies with "mapping values are not allowed".)
- **The first-boot go2rtc auth window (S9-04) is closed here**: the command
  line adds go2rtc's inline `-c api.username=... -c api.password=...` pairs,
  so the sidecar starts authenticated even before the server's first push.
  The image's entrypoint is bare tini, so the command must name `go2rtc`
  itself. The mechanism was proven in both directions (mutations below), and
  one more fact fell out: the server's push persists to `/config/go2rtc.yaml`,
  so after the first push the volume alone keeps restarts authenticated — the
  inline pairs matter exactly for the first boot on an empty volume.
- **No models volume**: the exported ONNX is baked into the detector image and
  the image digest is its provenance; a named volume would outlive the image
  it was seeded from.
- Same project name `nvr` as dev: dev and prod are two ways to run one
  installation and share its volumes — verified the hard way when a dev-era
  postgres volume rejected the prod password (`failed SASL auth`), which is
  the honest consequence of that choice, not a bug in either file.

Mutation evidence — each break kills its criterion, restore re-green (`diff` clean):

| Mutation | Observed failure |
| --- | --- |
| drop `GO2RTC_PUBLIC_URL` from .env | config refuses: "required variable GO2RTC_PUBLIC_URL is missing a value: ..." |
| drop `WORKER_TOKEN` from .env | config refuses, naming `NVR_WORKER_TOKEN` on the detector |
| inline `-c` pairs removed, fresh go2rtc volume | first boot answers `200` credential-less — the window is open again |
| (as-found) command without `go2rtc` first | `[FATAL tini (7)] exec -config failed` — tini's entrypoint needs the binary named |
