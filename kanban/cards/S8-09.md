# S8-09 — AuditPage + routes/nav role gating

Routes /login, /auth/callback, /live, /events, /events/:id, /cameras, /cameras/:id, /settings, /audit with role-aware nav.

## Exit criteria

- [x] viewer sees no Settings tab
- [x] deep links survive reload
- [x] audit list answers who did what

## Verification

`cd web && npm run test:run`

## Notes

**Three obligations landed here from the cards built before the shell existed**
(2026-11-06), so this card is the one that settles them:

- **Mount `EventsPage` at both `/events` and `/events/:id`.** S8-06's drawer is a
  URL, not modal state: the page reads `useMatch('/events/:id')` and renders
  `EventDetail` when it matches, so a drawer is deep-linkable and closing it
  returns to `/events` with the filters intact. If the route table points
  `/events/:id` at something else, the drawer silently never renders. The plan's
  route list already says both; this is the reason it must stay that way.
- **Mount `CamerasPage` at both `/cameras` and `/cameras/:id`.** The same shape,
  for the same reason (S8-07): the camera editor reads
  `useMatch('/cameras/:id')` and renders the row form plus the zone editor over
  the list it already has — the list route answers the full `cameraView`, zones
  included, so a deep link to a camera is one request and survives a reload. A
  route table that sends `/cameras/:id` elsewhere loses the zone editor with no
  error anywhere.
- **Take over the live feed's lifecycle.** S4-06 shipped `LivePage` as the only
  caller of `useRealtime.getState().connect()`, and it deliberately never calls
  `disconnect()` — one socket per tab, and a tile unmounting must not drop the
  feed the next page reads. So today a console that mounts no wall has no feed.
  The shell should open the feed once for a signed-in session and decide where
  `disconnect()` belongs (logout, unmount, or nowhere); the stale/refused banner
  S8-10 built the state for also has no home until this card gives it one.

## What landed

- **`server/api/audit.go`** — `GET /api/audit` (admin group): filters `actor`
  (username), `action`, `target_id`, `outcome` (named four words or 400),
  `from`/`to` (RFC3339 or 400), `limit` (default 50, max 200), `offset`;
  `limit+1` probe row so `truncated` is a fact; answers
  `{audits, count, limit, offset, truncated}` newest-first with `details`
  parsed to a map (null when the row has none). The read is deliberately NOT
  audited: no read verb exists in `models/audit.go`, and a ledger read that
  writes rows moves the page count under the operator reading it.
- **`web/src/api/audit.ts`** — the server's shape verbatim + the four outcome
  words + URL filter helpers (`actor`, `action`, `outcome`, `target_id`).
- **`web/src/pages/AuditPage.tsx`** — admin gate drawn before any request;
  filters live in the address bar (submit, not per-keystroke; a filter rewrite
  drops `offset`, so the page reset is free); rows carry name, roles·provider,
  verb, `→ target`, outcome word, details JSON, source ip; `older`/`newer`
  paging through `?offset=`.
- **`web/src/App.tsx`** — the shell: the full route table with BOTH pairings
  (`/events`+`/events/:id`, `/cameras`+`/cameras/:id`); signed-out guard
  (`/login` and `/auth/callback` stay reachable, everything else `Navigate`s);
  role-aware nav (Settings/Audit only for `hasRole('admin')` — hiding is
  courtesy, the server's `RequireRole` is the gate, and the pages still refuse
  deep links themselves); the feed's owner (`connect()` when a session is
  signed in — idempotent, so the wall asking again costs nothing — `disconnect()`
  when the session ends or the shell unmounts); the stale/refused banner reads
  the store's own `status`/`reason` and says nothing when the feed is current.
- **`web/src/main.tsx`** — mounts `BrowserRouter > AuthProvider > App`; the
  router lives outside `App` so the suites can mount the shell under
  `MemoryRouter`.
