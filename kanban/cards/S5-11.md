Three people in `bus.jpg`, the best at conf 0.890 — over the plan's 0.5 — with the box
inside the photo's bounds and more than half a percent of its area. The other test in
the file asserts the exported model is the shape the worker expects: input `images`,
output `output0`, providers `['CPUExecutionProvider']`.

- **The planted tensor** is one anchor per row of a `[1, 84, 8400]` array: class 0 at
  conf 0.9, centre (120, 100), size (40, 100) decodes to `(100, 50, 140, 150)`, and a
  traffic light at conf 0.99 decodes to nothing.
- **NMS is pinned from both sides.** `(0,0,100,100)` against `(20,0,120,100)` is IoU
  8000/12000 = 0.667 → one box, the conf 0.90 one. `(0,0,100,100)` against `(60,0,160,100)`
  is 0.25 → two. The card asked for "an IoU 0.62 pair": with two equal 100×100 boxes
  offset sideways the IoU is `a/(100+a)` for an overlap of `a`, which tops out at 0.5, so
  the 0.62 case is planted **nested** instead — `(0,0,80,80)` inside `(0,0,100,100)` is
  6400/10000 = 0.64 — and the survivor is the smaller box, listed second, so an NMS that
  keeps boxes by area or by input order fails it while the centres (14 px apart) would
  fool a centre-distance suppression.
- **No test touches the network**, proven by running the whole fast suite in a container
  started with `--network=none`: `123 passed, 2 deselected in 9.67s`. The stub server that
  counts the retry attempts binds 127.0.0.1, which still exists with no network; nothing
  reaches PyPI, go2rtc, or the server.

## Notes

The slow marker keeps the model/decode contract in CI without costing minutes per push.

- **The suite found four real bugs and one plan slip**, and none of them were in the tests:
  `MjpegStream` reconnecting forever over a scripted source (S5-02), a track aged on the
  frame it was born on (S5-04), `_frame_size` called as a method that was a module function
  (S5-05), and an event age ceiling that never fired while hits kept landing (S5-06). The
  slip is the centroid example (S5-05). A fake-only suite would have shipped all four.
- **Two seams carry the whole suite**, and both exist so a test asserts instead of sleeps.
  `RecordingOpener`/`StubMjpegResponse` script go2rtc's multipart body and — critically —
  stop the stream when the script runs out. `StubSession` scripts the transport and raises
  when a test's script runs out, so an unexpected call is a finding rather than a hang; the
  pipeline tests hand it a `default` because they are testing reconciliation, not the
  transport.
- **`StubServer` is a real `ThreadingHTTPServer` on 127.0.0.1**, used only where the
  criterion is a *count of attempts*: the server counts what it was asked, which is the only
  way to assert "500, 500, 200 → 3 attempts" rather than "the client believes it tried three
  times".
- **`FakeSleep` and `FakeClock` are injected everywhere**, so the 5/10/20/40/60 s backoff and
  the 10 s idle close cost microseconds. A suite that sleeps through its own timeouts is a
  suite nobody runs twice — and this one had to be run dozens of times.
- **The smoke skips, and says where to get what is missing**: no `yolov8n.onnx` points at the
  image build (S5-12) and `scripts/fetch-fixture.sh` (S10-01); no `bus.jpg` points at the
  fetcher and `testdata/fixtures.json`. Both artifacts are gitignored, so a clone that has
  never built the image sees a skip with an address, not a failure.
