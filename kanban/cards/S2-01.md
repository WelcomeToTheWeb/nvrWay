# S2-01 — auth/jwt.go: HS256 access + refresh with rotation and reuse detection

## Deliverable

NewJWTAuth(secret), Issue(userID, roles, ttl), Verify(token) -> *Claims, IssueRefresh, VerifyRefresh. Access TTL 30 min, refresh 14 d, rotation with rotated_from reuse detection.

## Exit criteria

- [x] the alg in the token header is never trusted (HS256 only)
- [x] expired/foreign-secret/garbage tokens each fail with a distinct error
- [x] a rotated-away refresh token is rejected when replayed (reuse detection)
- [x] claims carry userID + roles and round-trip through Verify

## Notes

Copy OurWay's auth/jwt.go API shape, not a new design.

Delivered as `server/auth/jwt.go` (396 lines). The plan's API is exact —
`NewJWTAuth(secret)`, `Issue(userID, roles, ttl)`, `Verify(token) -> *Claims`,
`IssueRefresh`, `VerifyRefresh` — plus OurWay's two revocation habits
(`Deny(jti, exp)` for logout, `BumpUserGen(userID)` for a password change) and
`IssueNamed`, which is `Issue` with the username claim the audit ledger needs.

Decisions recorded here because they are decisions:

- **HS256 only, enforced twice.** `parse` reads the header first and refuses any
  `alg` that is not `HS256` with `ErrTokenSigningMethod`; the parse repeats it
  with `jwt.WithValidMethods(["HS256"])`, and the keyfunc refuses a non-HMAC
  method. A header saying `alg: none` or RS256 is refused on the algorithm, not
  on the signature it happens to carry.
- **The refusal reasons are named sentinels**: `ErrTokenExpired`,
  `ErrTokenSignature`, `ErrTokenMalformed`, `ErrTokenSigningMethod`,
  `ErrNotAccessToken`, `ErrNotRefreshToken`, `ErrTokenRevoked`,
  `ErrTokenGenerationStale`, `ErrRefreshUnknown`, `ErrRefreshReused`,
  `ErrRefreshSubjectMismatch`. The library's error stays reachable through
  `Unwrap`; nvrWay's sentence is in front.
- **TTL defaults are the models'**: `ttl <= 0` means `models.AccessTokenTTL`
  (30 min) / `models.RefreshTokenTTL` (14 d). Issuers `nvrway` / `nvrway-refresh`.
- **The refresh token is a signed JWT** (type=refresh) and the sessions row
  stores its SHA-256. `models.NewRefreshToken` mints an opaque string; using it
  for the replacement would have given one credential two shapes, which is how a
  refresh route ends up accepting one and rejecting the other. `RotateRefresh`
  now issues the replacement with `IssueRefresh`.
- **Rotation and reuse detection live in `RotateRefresh(sessions, token)`** over
  a `SessionWriter` interface (`GetByTokenHash` / `Rotate` / `RevokeAllFor`),
  satisfied by `store.SessionStore`. auth links no store, so a replay is testable
  without a database. `models.ErrSessionRotated` is the shared sentinel — moved
  from `store` to `models`, next to the row it describes, with
  `store.ErrSessionRotated` kept as an alias so Step 1's store callers are
  unchanged.
- Reuse closes **every live session of the account** and returns
  `ErrRefreshReused`; the old access token is denied at rotation.
