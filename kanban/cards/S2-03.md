# S2-03 — store/bootstrap.go: seed roles + break-glass admin, recorded in settings

## Deliverable

Seed roles admin/operator/viewer; create BOOTSTRAP_ADMIN_USER with role admin only when BOOTSTRAP_ADMIN_PASSWORD is non-empty and no admin exists; record settings key bootstrap_admin_seeded_at so it never re-seeds.

## Exit criteria

- [x] deleting the admin account does not re-create it on next boot
- [x] empty password creates no local admin
- [x] the three builtin roles exist after a cold boot

## Verification

`docker run --rm -v $PWD/server:/src -w /src golang:1.26 go test ./store -count=1 -run Bootstr`

## Notes

This is the path verify.sh step 2 depends on.

Deviation, recorded in place: the plan's Step 2 sentence ends at "seeds", but the
seeding must happen on a real boot for an operator to benefit from it, so
`server/main.go` is in the card's paths and calls `st.Bootstrap(cfg.BootstrapAdminUser,
cfg.BootstrapAdminPassword)` right after the store opens, logging the account it
created. The boot log's auth-mode summary (Step 1's) predicts this behaviour;
now it is the behaviour.

`server/store/bootstrap.go`: `Store.Bootstrap(user, password) (seeded bool, err)`
— roles first, then the account.

Decisions recorded here because they are decisions:

- **The marker is a settings row (`bootstrap_admin_seeded_at`), not a property of
  the account.** A boot that seeds from "no account holds admin" re-creates the
  account an operator deleted. The marker has to outlive the row it describes,
  which is why it lives in settings.
- **Skip without a marker when someone already holds `admin`.** An SSO-provisioned
  administrator is a way in; the break-glass account is not seeded beside it, and
  nothing is recorded — so an installation that later loses every administrator
  gets the local account back. The two rules (never resurrect, always be able to
  get in) are the same rule read twice, and the marker's absence is what keeps
  them from contradicting each other.
- **A username already taken is a refusal, not a takeover.** Seeding does not
  change an account it did not create: not its password, not its roles. It
  refuses with the username named, and records nothing.
- **`store` → `auth` is the import direction.** `auth` imports `models` only, so
  the seeding can hash without a cycle, and `auth` stays the one place that knows
  how a password becomes a stored string. `SetPassword` takes the hash.
- **The seeded account carries the `admin` role only** — via `SetRoles`, which
  replaces rather than appends — and nothing else: no name, no email, provider
  `local`, status `active`, password from `BOOTSTRAP_ADMIN_PASSWORD` verified
  against the stored argon2id string.
