# S3-03 — Camera API: CRUD, probe, snapshot, slug rules

## Deliverable

## Exit criteria

- [x] delete removes rows + local media + enqueues remote purge jobs

## Notes

The seeder in scripts/dev.sh --demo uses this route, not the DB (Step 10).

**Observed** 2026-11-02: the command above, `ok  nvr/server/api 1.258s`.

Decisions this card forced, recorded in `api/cameras.go`:

- **The camera list is `{"cameras": [...]}`, not a bare array** — the shape every
  other collection in this API answers with, so a list response can grow a total
  later without becoming a different endpoint.
- **A PUT merges onto the stored row.** `Store.Update` deliberately writes every
  mutable column, so a console that sends only the field it edited would zero the
  retention days set from another screen. The payload binds into pointers.
- **A write whose config the sidecar did not take answers 502, and the row stays.**
  Rows are the truth (the recorder polls them, boot re-applies); a 200 here is an
  operator who believes the camera is live.
- **The row is validated through the renderer at write time.** A detection tap with
  no frame rate is a camera that is green in the tile and detecting nothing
  forever; asking the renderer turns that into a 422 naming the knob.
- **A camera with no producer is a 404 on the snapshot, not a 200 with no bytes.**
- The delete is admin-only: deleting a camera destroys its footage ledger. Its
  refusal lands as a `camera.delete` row with outcome `refused`, from Step 2's
  denial registry (which pre-named these routes' verbs).
