# S5-10 — Internal worker API: detector config payload + signals intake

## Deliverable

GET /api/internal/v1/detector/config (only DetectionEnabled && Active cameras, providers split from DET_PROVIDERS, event_max_seconds) and POST /api/internal/v1/signals answering {accepted, events[]}.

## Exit criteria

- [x] unknown camera_id -> signal skipped with "unknown camera"
- [x] camera with detection disabled -> skipped with "detection disabled"
- [x] snapshot_base64 over 250 KB stored as absent, event survives
- [x] record_mode=events signal opens the recorder window (Recorder.OpenWindow)
- [x] routes sit behind InternalAuthMiddleware (S2-08)

- **The payload is asserted key by key** against a map written out in the test: the top
  level is `providers`, `settings`, `cameras`; settings is `event_max_seconds`,
  `det_width`, `det_height`, `det_fps`; a camera is `name`, `stream`, `record_mode`,
  `sensitivity`, `min_area_ratio`, `zones`, `floors`. A camera's `stream` is `<slug>_det`,
  `zones` carries the polygon exactly as the console drew it plus `min_confidence`,
  `dwell_seconds` and `enabled`, and `floors` is `[]` rather than `null` because the worker
  iterates it. A paused camera, a camera with detection off and a disabled zone are each
  absent; a camera list with nothing in it is `[]`, not `null`.
- **The gate is asserted on both routes**: no token → 401, the browser token → 403, the
  worker token → 200; `WORKER_TOKEN` empty → 403 `internal api disabled` (S1-06).
- **The state machine is mirrored**: `open` inserts, `extend` moves the window and appends
  objects, `close` sets `ended_at`. A second `open` on the same `event_key` inserts nothing
  (`CountEvents` stays 1) and writes no second snapshot — the first picture is the one that
  proves the event.
- **The snapshot goes through the storage backend**, not the filesystem:
  `TestInternalSignalsWriteTheSnapshotTheOpenCarried` reads `snapshots/<event_id>.jpg` back
  through `storage.GetFile` and compares bytes. An oversized one is stored **absent** —
  `GetFile` returns `storage.ErrNotFound` — while the event row keeps its `first_ts` and its
  objects.
- **The recorder window opens only for an `events` camera**, through the `Recorder.OpenWindow`
  seam S4-05 built, and a deployment with a nil recorder still records events (the test
  asserts both).

## Notes

No /window route: windows open from signals (plan Step 5).

- **A refusal is a 200 with a per-signal `error`, not a 4xx.** The plan's contract (line 183)
  is `{"accepted":N,"events":[{"error":"event closed"}]}` with a 200, and the worker's retry
  rule (S5-08) is "4xx is not retried". A 403 for "this camera's detection is off" would make
  the worker retry a fact that will never change, and a 500 for one bad signal in a batch of
  forty would lose thirty-nine. So unknown camera, detection off, camera not active, event
  already closed and event row gone are all a 200 with the reason. The 4xx that remain are the
  ones waiting cannot fix: a body that is not JSON, and a `ts` that is not RFC3339.
- **The worker's `ts` is validated and thrown away.** `time.Parse(time.RFC3339, …)` proves the
  shape — a malformed one is refused, because it means the worker is broken and the next forty
  signals will be too — and then `first_ts`, `last_ts` and `ended_at` come from `s.now()`. A
  camera with a wrong clock must not file its footage in 1970, and the console's timeline is
  the server's clock (S6-03).
- **`record_mode` is read from the camera row, never from the signal.** The worker copies the
  mode into every signal it sends, so a config poll one beat stale would otherwise open a
  recorder window for a camera the operator switched a second ago — or fail to open one. The
  row is the authority; the signal's copy is a hint, and the test asserts the two agree on the
  camera it built.
- **The severity floor is the camera's `sensitivity`, clamped to 0.05..0.95.** A zone asking
  for 0.99 on a camera set to 0.45 would open an event for every leaf; a zone at 0.01 would
  open one for the encoder's noise. The clamp is the one the console applies too (S8-03), so
  the two ends cannot disagree about what a slider means.
- **A nil recorder is a supported state**, not a test convenience: detection can be enabled on
  a deployment whose recorder is not wired yet, and the events still have to be recorded.
- **`MaxSignalSnapshotBytes = 250 * 1024` is the server's cap; the worker's is 200 KB.** The
  worker tries to stay under; the server decides what "too big to store" means, and the two
  numbers are deliberately different — a snapshot that squeezed over the worker's cap still
  arrives, and the server's answer is "no picture, same event", not "no event".
