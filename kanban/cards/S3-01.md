## Notes

Browsers talk to go2rtc's /api/ws directly (Step 8) — v1 needs no server relay.

Retry policy is 1 request + `DefaultRetries`=3, `DefaultBackoff`=500 ms, and the
confirm window is `DefaultConfirmFor`=5 s polled every 250 ms. A canceled context
stops the loop: re-asking after the caller is gone spends the request budget on a
dead request.

`Confirm` is a real check, not a formality: a config go2rtc wrote and did not
apply is a camera row the operator saved while the sidecar served the old file,
which is the drift S3-05 forbids.

Verified against the go2rtc source (master, 2026-11-02) before writing the
client; two facts changed the implementation, both recorded in `client.go`:

- `internal/streams/api.go` — `DELETE /api/streams` removes `delete(streams, src)`:
  the param it reads is **src**, not `name`. A `?name=`-only delete answers 200 and
  deletes nothing, so `DeleteStream` sends `?name=<slug>&src=<slug>`.
- `internal/api/config.go` — `POST /api/config` validates the YAML and answers
  **500** with the parse error in the body, and **410 Gone** when go2rtc has no
  config file path. Those are decisive answers, so a 4xx and a 5xx-with-a-body are
  `ErrStreamRejected` (never retried); only transport failure and a bare 5xx get
  the 3 retries. `PATCH` merges, which is why the whole-file `POST` is the write
  path (a merge keeps a deleted camera in the file — the drift S3-05 forbids).

## Live-sidecar verification (2026-11-02, go2rtc 1.9.15, revision 7c05066)

Ran the client against a real sidecar (`alexxit/go2rtc:latest`) rather than the
fake. Every S3-01 claim held; one shape the fake did not cover was missing.

- `GET /api/streams` answers producers as **`[{"url": "exec:ffmpeg …"}]`** and
  `consumers: null`. The client accepted it (so did no probing of the plan's
  "two shapes"), but labelled the producer with the raw JSON — a console tile
  naming a producer with a JSON blob. `endpointLabels` now reads `address`, then
  `url`, then `format`, with a test pinned to this exact shape.
- `DELETE /api/streams?name=back-patio` → **HTTP 200, the stream is still there,
  the config file unchanged.** `DELETE /api/streams?src=back-patio&name=back-patio`
  → the stream is gone. The delete that deletes nothing is not a forecast; the
  client sends the pair, and asserts both.
- `POST /api/config` on a sidecar started with inline config (`-c '{…}'`) →
  **HTTP 410**, verified.
