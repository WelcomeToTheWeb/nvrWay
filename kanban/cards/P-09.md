# P-09 — Mirror the cards into the DeepSeek Harness workspace board (kanban/harness_board.py)

## Deliverable

`kanban/harness_board.py` folds `kanban/cards/*.md` into the harness board (`KANBAN.json`) so the agent's own board shows the whole project, not just this session's cards. Stdlib only, `--check` included, wired into `kanban/pre-commit.sh`.

## Exit criteria

- [x] every repo card has exactly one harness entry, filled on every field
- [x] a hand-written field survives any number of runs
- [x] `--check` fails when the board lags a card

## Verification

`python3 kanban/test_harness_board.py && python3 kanban/harness_board.py --check`

## Notes

**Why this exists.** The harness board (`KANBAN.json`, read and written by the agent's `board_*` tools and shown on its web page) carried only this session's cards — six of them — while the repo board carried 116. Asked to fill it out, the user chose to mirror the whole repo board rather than keep the two separate. **This supersedes the earlier decision recorded on P-06's lines that the two boards must not duplicate each other.** The repo board stays the source of truth: every mirrored entry ends with `Source of truth: kanban/cards/<id>.md`, and the mirror writes no sentence the card does not already contain.

Observed 2026-11-05:

```
$ python3 kanban/test_harness_board.py
Ran 25 tests in 0.016s
OK

$ python3 kanban/harness_board.py
harness board: 116 cards mirrored -> KANBAN.json (0 new, 0 descriptions filled, 2 harness-only kept)

$ python3 kanban/harness_board.py --check
harness board: 116 cards, 0 drift(s)          # exit 0
```

Test-first: `kanban/test_harness_board.py` was written and run before the module existed — `ModuleNotFoundError: No module named 'harness_board'`, the same red P-06's mirror started from.

**Two rules make it safe to run beside the harness's own board tools, which write the same file.** Only empty fields are filled, so a `rationale`/`summary`/`rejected` written by hand through `board_update` survives any number of runs (pinned by `test_hand_written_fields_are_never_overwritten`); and a harness-only card with no repo counterpart — the two follow-ups — is left exactly where it is (`test_harness_only_cards_survive`). A card deleted from `kanban/cards/` does lose its entry, which is the point of a mirror.

**`--check` checks invariants, not text.** The extraction is lossy by design and a hand-written field is legitimately different from an extracted one, so byte comparison would report drift forever. It checks what matters: one entry per card, status parity through the mapping, no empty `description`/`rationale`/`tags`, and a Done card carrying `summary` and `rejected`.

**Status mapping.** The harness has no Blocked column, so `blocked → todo` plus a `blocked` tag plus the reason as the description's first line. `backlog → todo`, `in-progress → in_progress`, `done → done`.

**Three extraction bugs, each caught by reading the output rather than trusting the script** — all three are pinned by a named test, because each one put a false statement on the board before it was fixed:

- **A bare bold heading is not a decision.** `**Decisions, with the reason.**` labels what follows; taken as a decision it became a card's whole summary.
- **Deviations are usually list items.** The corpus writes `- **Two gates, not one.** …`, so the paragraph starts with `- `, not `**`. Testing only paragraphs that *start* with `**` missed every one — 40 cards recovered a real recorded rejection, 40 → 60.
- **The first paragraph can be the rejection too.** Excluding the summary's opening from `rejected` silently dropped the only deviation on 8 cards.

Also: several cards continue the record under their own heading after Notes (`## What closed it`, `## Probe, 2026-11-02 …`), so Notes is read **to end of card**, not to the next `## `.

**The honest-absence line, and its limit.** 26 of the 86 Done cards record no declined alternative — Step 0/1 verification records and P-0x process cards. They get *"No rejected alternative is recorded on this card… kanban/cards/<id>.md is where to add it."* That is a **verified absence**: written only where the deviation scan found nothing, with three of them (S1-01, S1-06, P-05) read by hand to confirm. It must never be extended to a card without running the scan.

**Deviation — the first pass wrote that line onto cards that did record a rejection.** S2-08 and S3-02 both carry "**Empty `WORKER_TOKEN` is 403, not 401.**" and "**A zero frame rate is refused, not rendered.**"; the list-item bug above is why they were missed. Had the output not been read, the board would have shipped 44 false statements.

**Simplification made during review.** A `BARE_HEADING` regex was written to exclude label paragraphs from summaries. The corpus has eight of them and **all eight are under 120 characters**, so the length floor already covers every real case; the regex was removed rather than kept as unearned generality. The test that was supposed to guard it was vacuous — it asserted the summary was not *equal* to the heading, which stayed true while the heading sat inside the summary — and was rewritten to assert the heading does not appear at all.

**One test assertion was wrong, not the code.** `test_a_duplicated_card_is_reported` asserted the word "twice"; the checker says "mirrored 2 times". Fixed the assertion to name the card and the count of problems, not the phrasing.

**Mutation evidence** (each reverted, suite green after):

| Mutation | Failing tests |
| --- | --- |
| overwrite fields unconditionally | the hand-written-preservation test + the idempotence test |
| bold lead only at paragraph start (the original bug) | exactly the list-item deviation test |
| drop the summary length floor | exactly the bare-heading test |
| drop the `BLOCKED` double-prefix guard | exactly the blocked-prefix test |
| skip YAML quote stripping | both title tests |
| `check()` ignores status parity | exactly the lagging-status test |
| drop harness-only cards | exactly the survive test |

**Hook.** `kanban/pre-commit.sh` runs the mirror after `board.py`, but only when `KANBAN.json` already exists in the tree — a plain clone never grows one, and the file is gitignored.
