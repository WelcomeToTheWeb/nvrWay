# S9-10 — the skeletons get their decisions, or the users write them for us

## The finding

S0-02 left four docs as skeletons: every heading named the decision it owed,
and the content was "Answer: …". By Step 11 the code had answered all of them
— but only in card files and code comments, which no operator reads. The plan
called these documents "decisions-bearing: they are the record of why v1
stops where it stops", and a doc that only describes behavior without the
rejected alternative is a changelog.

## The fix

**architecture.md** — every skeleton section written: the pipeline diagram
with the one-process/sidecar/container line drawn and justified; a Components
table that states each package's **never-list** (the part a maintainer must
not violate by accident); the five data flows with their load-bearing
constants; the clock rule (worker `ts` validated then thrown away, and the
stated cost); the single-instance rule (what a second server actually breaks
— duplicated footage and half-deleted trees, failing quietly); live view with
the three P-14/P-15/P-16 consequences; the WS hub and why no Redis is the
same answer as the single-instance rule; auth/tenancy including the stated
single-tenant decision; detection with the sizing claim stated as a dev-box
measurement, not a benchmark; the inference host stating that **no CUDA claim
has ever been executed here**; retention with the force-delete half of the
protection window stated, not just the protection; a Technology Choices table
with a rejected alternative per row; the scaling path ordered by which
constraint binds first; and a new "Gaps v1 leaves open, stated" section
collecting the three named gaps with pointers.

**installation.md** — sections 1–6 and 8–15 + Troubleshooting written from
prompts into content: the port table naming what may face a LAN and what must
never face a WAN; the secrets section stating what each empty value costs;
worked MinIO/R2/B2/NFS examples; the retention math table with the
bytes-per-day arithmetic; the proxy's three obligations; § 12 stating plainly
that **the GPU overlay does not exist yet** (S9-06 open) rather than
describing a planned file as shipped; the nine verify gates; and five
troubleshooting entries each naming the check to run first.

**configuration.md** — two structural defects fixed: the env table was split
in half by the S3-07 section (rows 57–72 orphaned with no header, rendering
as a broken table), and the P-14 section was wedged mid-paragraph inside the
PUBLIC_BASE_URL explanation (a P-14 commit artifact) — now its own H2.

**api.md** — the ToC filled; the route tables were already current (each step
card had filled its own), spot-verified against the router.

## Exit criteria

- [x] every env var in config.go documented with its default — audited by
      script, not by eye (evidence below)
- [x] the redirect URI stated verbatim: `${WEB_URL}/api/auth/sso/<provider>/callback`
      (installation.md § 7, with the concrete default-port example and the
      422-that-prints-the-string note)
- [x] the three v1 gaps (remote seek, ONVIF events, GPU verification) are
      stated in docs, not discovered by users — architecture.md
      "Gaps v1 leaves open, stated", each with its decision section
