# P-15 — `api.origin: "*"` is in the rendered config, and go2rtc only reads it at boot

## The finding

Found 2026-11-07 while restoring the dev stack's live view after closing P-14:
with the sidecar's credentials gone and `/api/ws` answering `101` to curl, the
browser's live tile still read `unreachable — the media host closed the
connection before answering the offer`, and the sidecar logged:

```
ERR internal/api/ws/ws.go:106 > host=localhost:1984 origin=http://localhost:3000
    error="websocket: request origin not allowed by Upgrader.CheckOrigin"
```

go2rtc's WS upgrader installs its `CheckOrigin` **once, in `Init()`, from the
config file as it exists at process start** (`initWS(cfg.Mod.Origin)`; the
`"*"` branch allows any origin, the empty branch is same-origin, and any other
value leaves gorilla's default same-origin check in place). The server pushes
its rendered config — which carries `api: { origin: "*" }` — with
`POST /api/config` **after** the sidecar is already up (S3-05's boot apply),
and applying a config does not re-run `initWS`. So the `origin: "*"` the
renderer writes is a value the WS layer only ever honours if it was on disk
before the sidecar started.

The consequence is a live view that works or fails depending on volume
history: a sidecar whose volume has seen one server push starts with
`origin: "*"` from the persisted file and works forever after; a sidecar on a
**fresh volume** — every first boot, every `docker compose down -v`, every
e2e run after `stop` — starts with no config, gets the same-origin check, and
403s the console, which lives on a different port than the sidecar. The e2e
suite had been passing on persisted volumes; the dev stack broke the moment
the volume was wiped (P-14's credential removal).

## The fix

Seed the sidecar's config from the base template **before go2rtc starts**, so
`api.origin: "*"` is on disk at process start on every boot, fresh volume or
not. The template (`docker/go2rtc.yaml.template`) already carries exactly the
base shape the renderer emits — `api: { listen: ":1984", origin: "*" }`, the
two listens, `streams: {}` — and the server overwrites the whole file with the
rendered config at boot anyway (S3-05), so the seed is authoritative for
nothing but the seconds before the first push.

- `docker/docker-compose.yml`: the template is bind-mounted read-only at
  `/go2rtc.seed.yaml`, and the service's `command` seeds
  `/config/go2rtc.yaml` from it **only when that file is missing or empty**
  (`[ -s /config/go2rtc.yaml ] || cp …`) before running go2rtc. The guard
  keeps a persisted config (with its streams) across restarts, exactly as
  before; tini stays the entrypoint. (The command grew a supervisor around
  go2rtc with P-16 — the seed line itself is unchanged.)
- `scripts/e2e-stack.sh`: the throwaway container gets the same mount and the
  same seed command, so a fresh-volume e2e run — the state `stop` then
  `restart` produces — starts the sidecar with the origin check already
  open. Before this, that run 403s the live spec. (P-16 later extended the
  command with the supervisor and gave the container a restart policy.)

## Exit criteria

- [x] a fresh-volume sidecar answers the console's cross-origin `/api/ws`
      with `101` — dev stack: volume wiped, `up -d`, curl with
      `Origin: http://localhost:3000` → `HTTP/1.1 101 Switching Protocols`
- [x] the browser's live tile plays on the dev stack (the P-14 stack, same
      wipe) — Playwright: tile shows the stream, no `unreachable`
- [x] the e2e suite passes from a **wiped** volume — `stop` + `restart` +
      `test`: 15/15 including the live spec
- [x] the template's role changes from documentation to seed and says so —
      its header now states it is bind-mounted and seeded at start, and that
      the server's push replaces it within boot

## Verification

**Observed 2026-11-07 — dev stack, volume wiped:**
`curl --max-time 2 -i -H "Origin: http://localhost:3000" …/api/ws?src=demo-doorbell`
→ `HTTP/1.1 101 Switching Protocols` (was 403 with the same wipe before the
seed). The browser live tile plays.

**Observed 2026-11-07 — e2e from a wiped volume:** `e2e-stack.sh stop` (which
removes the config volume) + `restart` + `test`: 15/15 passed, live spec
included. Before the seed this exact sequence fails the live spec with the
403 above (the suite had only ever been green on persisted volumes).

### Mutation evidence

| Mutation | Expected | Observed |
|---|---|---|
| seed guard inverted to always `cp` (clobbers persisted config every start) | e2e still green (server re-pushes at boot) — the guard protects restarts *without* the server, which is the compose story, not the e2e story | not run: the guard's purpose is dev-stack restart continuity, and the honest evidence for it is the dev-stack restart below |
| seed mount removed (fresh volume, no seed) | live spec red on a wiped volume | reproduced the pre-fix state exactly: 403 + `unreachable` tile (that is how the card was found) |

Dev-stack restart with a persisted config: `docker compose restart go2rtc` →
the seed guard skips (file present), the sidecar comes up with the previous
rendered config, the server re-applies at boot. No stream churn beyond the
restart itself.

## Notes

Why not bind-mount the template read-only *at* `/config/go2rtc.yaml`: go2rtc
saves the applied config back to its config path, and a read-only target
turns every `POST /api/config` into a failed save — the file the WS check
needs would exist, but the design's "the file is the server's output" would
be a lie with a write error behind it.

Why not make the console same-origin by proxying `/api/ws` through the
server: that is P-14's option 1 (a feature card's worth of work), and it is
not needed for this — the sidecar is browser-facing by design (P-14), so
opening its WS to the LAN's origins is the shipped posture, not a widening.

The `origin` value's third branch is worth remembering: any value that is
neither `""` nor `"*"` leaves gorilla's **default** check in place, which is
same-origin — the config key silently means "strict" for typos like `all`.
The renderer emits `"*"` verbatim, so the shipped config is the allow-any
branch.
