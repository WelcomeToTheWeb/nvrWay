**go2rtc auth is boot-time config, not a runtime push.** The server renders
`api: { username, password }` into the config it POSTs (S3-02's
`renderListeners`), and go2rtc persists that push to `/config/go2rtc.yaml` —
but it initializes the auth middleware only at startup. So the first boot after
`up` is open, and auth enforces from the sidecar's next start: after
`docker restart nvr-go2rtc`, a credential-less call from another container
answers `401 Unauthorized` and an authenticated call answers 200. go2rtc always
passes localhost without auth (`local_auth` is off), which is why the sidecar's
own healthcheck needs no credentials — and why a host curl through the published
port is not a valid auth probe. The first-boot window is the honest state of a
dev stack whose API is loopback-published; closing it means seeding
`/config/go2rtc.yaml` before first start, which is a prod-file decision (S9-05).

Three healthchecks were wrong in the skeleton and are fixed here:

- detector: `pgrep -f nvr_detector` cannot run — python:3.12-slim ships no
  procps, so the check was always-unhealthy. PID 1 IS the worker (exec-form
  CMD), so the check greps `/proc/1/cmdline` — no new package.
- web: `wget --spider http://localhost:8080/` was always-unhealthy — busybox
  wget prefers `::1` and nginx's `listen 8080` is IPv4-only. The probe now names
  `127.0.0.1` (same fix in Dockerfile.web's HEALTHCHECK).
- go2rtc: had no healthcheck, so the server gated on `service_started`; it now
  probes `/api/streams` on localhost and the server gates `service_healthy`.

The `./testdata:/fixtures:ro` mount was relative to `docker/` — a path that does
not exist; it is `../testdata:/fixtures:ro`.
