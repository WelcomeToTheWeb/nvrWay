Test-first: `realtime.test.ts` ran red on `Failed to resolve import "./realtime"` before the module existed.

**The seven types are the server's, and so is the envelope.** `server/ws/hub.go` defines `event.new`, `event.update`, `event.close`, `camera.status`, `recorder.status`, `storage.queue`, `presence` — exported as `WS_TYPES` with a test asserting the set matches, so a type added on the server fails a test instead of being silently dropped. The payload is **not** at the top level: `Envelope` is `{type, payload, ts}`, where `ts` is the server clock in UTC. That clock is kept as `lastFrameAt`, because the console compares a segment's end with an event's start and a browser clock that drifts across timezones cannot be the measure of both. The first draft of the tests merged the payload into the frame — the shape the card's prose implies and the server does not send; reading `Envelope` before writing the handler is what caught it.

**Payloads are the server's own shapes**, read from the call sites rather than invented: `broadcastCameraStatus` (`{camera_id, slug, online, producers}`), `recorderStatus` in `server/media/segments.go` (`{camera_id, mode, segment_seconds, last_segment_at}`), the sweeper's `Report` for `storage.queue` (`force_deleted` is the number that means an upload outage outlasted the protection window), `Hub.Presence` (`{clients}`), and `eventView` for the three event types. `camera.status` and `recorder.status` are keyed by `camera_id`, not by slug — an id is what cannot be reused.

**`event.close` keeps the event and marks it closed.** The console is showing a card for that event; deleting the row makes it vanish under the operator's cursor.

**Deviation — "5 s backoff capped at 60 s" is read as doubling: 5, 10, 20, 40, 60, 60.** The plan does not say exponential, and a fixed five seconds needs no cap. The cap only means something if the interval grows, so it grows by doubling and stops at sixty. Asserted as an exact sequence against an injected scheduler, not against a wall clock.

**Deviation — the token is re-read for every attempt.** A refresh rotates the access token, and a reconnect holding the old one is a 401 that looks like a dead server. `token` is a function, not a string, and a test that rotates the token between attempts pins it.

**The origin guard, and the limit of what the console can know.** `Hub.Handle` answers a rejected origin `403 {"error":"origin is not allowed"}` **before the upgrade**, so the browser sees only a socket that will not open — it cannot read that sentence. The card's criterion is that a rejected origin says so and that silent reconnecting is the failure mode to avoid, so after three attempts that never reach an open socket the store moves to `status: 'refused'` with a reason naming `WS_ORIGINS`, and keeps retrying at the cap.

**What that cannot be**: a diagnosis. A network that is genuinely down three times also reads `refused`, and the sentence is written as a conditional — *"if this console is served from a host the server does not know, add it to WS_ORIGINS"* — because that is all the evidence supports. It is not a claim about the cause. A socket that later opens clears it back to `open` with `reason: null`, which is the test that keeps the state from becoming a sticky verdict.

**Deviation — the store owns the stale state; no banner component exists yet.** The deliverable's last clause is a banner, and the card's paths and criteria are the flag. `stale`, `status` and `reason` are what a banner renders, and nothing renders them: the shell that would mount them is S8-09's routes card, and nothing calls `connect()` yet either. A banner built now would be a component with no place to live and no test that could see it in a page.

**Testability shape.** `createRealtime({token, WebSocketImpl, schedule, location})` returns the zustand store; `useRealtime` is the singleton the console uses, wired to `readAccessToken()`. Timers are injected rather than faked, so the backoff schedule is asserted as data.
