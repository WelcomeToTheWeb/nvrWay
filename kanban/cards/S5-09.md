# S5-09 — pipeline.py + __main__.py: per-camera thread and env entrypoint

## Deliverable

Frame (respecting DetectionFPS) -> motion gate -> model.run -> tracker.update -> zones.evaluate -> events.transition -> signal buffer. Env: NVR_SERVER_URL, NVR_WORKER_TOKEN, DET_PROVIDERS, DET_MODEL_PATH, DET_HTTP_TIMEOUT, DET_MAX_CAMERAS. Exit 0 on SIGTERM after flushing.

## Exit criteria

- [x] only DetectionEnabled && Active cameras are processed (from the config payload)
- [x] SIGTERM exits 0 with signals flushed
- [x] DET_MAX_CAMERAS respected
- [x] python -m nvr_detector boots against a stub server and logs the camera set it picked up

The suite: `python -m pytest tests/test_pipeline.py -q` → `18 passed in 6.90s`.

- **Threads and restarts.** `test_a_camera_that_raises_is_restarted_with_backoff_and_
  logged` makes the loop raise and asserts the restart waits were `[5.0, 10.0, 20.0]`,
  that the log names the camera and the exception, and that the camera is still being
  restarted when the worker stops. `test_a_camera_that_restarts_often_keeps_the_same_
  event_state` asserts the tracker and the event state survive the restart — the
  objects are built once per camera, not once per attempt — because a restart that
  dropped them would end every open event and re-mint its key.
- **Reconciliation.** Added, removed and changed cameras are each asserted, and
  `test_a_camera_whose_zones_were_rewritten_restarts_its_loop` pins the fingerprint
  rule: the payload changed, so the loop restarts and the new zone set does not inherit
  dwell timers from rules the operator deleted. A payload that merely re-sorts the same
  cameras restarts nothing.
- **The ceiling names its victims**: `worker: DET_MAX_CAMERAS=2, so 2 camera(s) were
  not started: garage, shed`.
- **Shutdown closes events.** `test_stopping_closes_open_events_and_flushes` asserts the
  close signal reaches the server and that `run()` returns the client's counters.

## Notes

- **The signal handlers are installed before the model loads.** The first version
  installed them after `YoloOnnx(...)`, and on a CPU build that takes long enough that a
  `docker stop` arriving during the load was a bare `KeyboardInterrupt` through the
  stack — no `worker: stopped` line, and a nonzero exit. `main()` installs them first
  and returns `EXIT_OK` when the stop was a signal, so `docker stop` is not recorded as
  a crash.
- **`DET_MAX_CAMERAS` is a memory ceiling, not a licence fee**: the plan's number is 12,
  the first twelve in the payload are started, and the rest are named. Silently dropping
  a camera means an operator believes a driveway is watched.
- **The worker never decides what a camera is for.** `record_mode`, `sensitivity`,
  `min_area_ratio`, the zones and the floors all come from the server's payload; the only
  things the worker adds are `GO2RTC_URL` and the model. That is what keeps the console's
  zone editor (S8-03) as the single place a rule exists.
- **A camera whose stream dies is not restarted**: `MjpegStream` reconnects inside its own
  loop with the same 5 s backoff, so the thread supervision is for exceptions in the
  worker's code, not for a dead feed. Both paths log; only one of them resets counters.
