# P-13 — the boot test's kill can arrive before the handler exists

## Problem

`tests/test_pipeline.py::test_the_environment_is_all_the_worker_needs_to_start`
failed intermittently with `assert -15 == 0`: the worker process died by the
default SIGTERM action instead of exiting 0 through its handler. Observed
3/3 failures on a pristine checkout (S9-07 session, 2026-11-06, before any of
that session's detector changes) and ~1/3 with them — pre-existing, not a
regression from the heartbeat work.

## Mechanism

`__main__.main()` logged `nvr_detector: server=...` (the line `boot()` waits
for) before registering the SIGTERM/SIGINT handlers — "Handlers before
anything slow" was true relative to the model load, but the log line was
*earlier still*. `boot()` matched the line and signaled immediately; when the
signal landed inside that window, Python died with -15 and the test's
`assert code == 0` failed. Cold runs (no pyc cache, slower import between the
two points) widened the window; warm runs usually won the race.

## Fix

Moved the boot log line after the handler registration — the line's content
does not depend on the handlers, and the test's `wait_for` now guarantees the
handler exists before the kill. The comment in `__main__.py` states the order
requirement so the next reader does not "tidy" the log back up.

## Observed

**Observed** 2026-11-06 — the flake reproduced on CI's first run of the new
build.yml (run 42330330282, `assert -15 == 0`, 1 failed 124 passed), exactly
as recorded. Fix: boot line after `signal.signal()`; the boot test then ran
**5/5 green in cold containers** (was 3/3 red), full fast suite 125 passed.
CI run 42330781985 reruns the pinned-toolchain gate with the fix.

## Verification

`pytest tests/test_pipeline.py` five times in a row, cold container each time.
