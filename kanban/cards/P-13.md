# P-13 — the boot test's kill can arrive before the handler exists

## Problem

`tests/test_pipeline.py::test_the_environment_is_all_the_worker_needs_to_start`
fails intermittently with `assert -15 == 0`: the worker process died by the
default SIGTERM action instead of exiting 0 through its handler. Observed
3/3 failures on a pristine checkout (S9-07 session, 2026-11-06, before any of
that session's detector changes) and ~1/3 with them — pre-existing, not a
regression from the heartbeat work.

## Mechanism

`__main__.main()` logs `nvr_detector: server=...` (the line `boot()` waits
for) at ~line 91, and registers the SIGTERM/SIGINT handlers at ~lines 104–117
— "Handlers before anything slow" is true relative to the model load, but the
log line is *earlier still*. `boot()` matches the line and signals immediately;
when the signal lands inside that window, Python dies with -15 and the test's
`assert code == 0` fails. Cold runs (no pyc cache, slower import between the
two points) widen the window; warm runs usually win the race.

## Fix (when taken)

Move the boot log line after the handler registration — the line's content
does not depend on the handlers, and the test's `wait_for` then guarantees the
handler exists before the kill. (Alternative rejected: making `boot()` wait
for a later line — the boot line is the right readiness signal for a worker
that may take a minute to load its model.)

## Verification

`pytest tests/test_pipeline.py` five times in a row, cold container each time.
