26 new tests: 16 in `go2rtc.test.ts` (the wire contract), 10 in `LivePage.test.tsx` (the wall). `package.json` is untouched — no dependency was added, and the player uses the browser's own `RTCPeerConnection` and `WebSocket`.

**The offline state was measured, not assumed.** The card says a camera with no producers shows offline, so before writing the player the behaviour was observed against a real `alexxit/go2rtc:latest` on this host:

```
$ docker run -d -p 1984:1984 alexxit/go2rtc:latest          # no config, no streams
# ws://…/api/ws?src=nonexistent  →  OPEN, then after the offer:
{"type":"error","value":"webrtc/offer: stream not found"}   # and the socket stays open

$ # a stream declared in config whose RTSP source will not connect:
$ curl …/api/streams
{"porch":{"producers":[{"url":"rtsp://127.0.0.1:5541/unreachable"}],"consumers":null}}
# ws://…/api/ws?src=porch  →  OPEN, then after the offer:
{"type":"error","value":"webrtc/offer: streams: unknown error"}
```

Two things follow, and both are in the code. go2rtc reports a failed offer as an **`error` message on an open socket**, not as a close and not as silence — so "offline" means *go2rtc said so, in its own words*, and the console repeats them rather than inventing a diagnosis. And a stream can be **declared with a dead source and still list a producer**, so the console cannot read `/api/streams` to decide whether a camera is up; the only honest signal is what the offer gets back.

**Deviation — the limit of that evidence.** The offer sent by the probe was a hand-written stub SDP, not one a browser produced. So the exact error string for an unfed stream under a real offer is **not** verified; what is verified is the shape of the failure (an `error` frame, socket open) and the `stream not found` case. Whether chromium's real SDP is accepted end-to-end is S8-12's Playwright card, and nothing here claims it.

**Deviation — no HLS fallback exists, and that is the criterion met, not missed.** The fourth criterion permits `hls.js` only *if WebRTC fails in the target browser*. It has not been shown to fail — it has not been run in a browser at all yet — so the fallback is not built and `hls.js` is not a dependency. The criterion is a guard against building it early; building it now would fail the criterion it satisfies.

**Deviation — a fifth tile state the plan does not list.** `{kind:'ended'}`: media was flowing and the socket closed. It is not the same sentence as one that never started, and calling a dropped live stream "unreachable" sends the operator to check the wrong thing. `connecting`, `playing`, `offline`, `unreachable`, `unsupported` are the plan's four plus this.

**Deviation — the `<video>` element is always mounted, and hidden until a track arrives.** Attaching a stream to a freshly rendered element would drop the picture, and the element has to exist before `connectLive` runs. So it is in the DOM from the first paint with `hidden` set, and the sentence below it is what is on screen. A hidden video is not the black box the criterion forbids; the test asserts `hidden` flips only on `playing`.

**The media host is the server's, never the bundle's.** `LivePage` reads `GET /api/v1/settings/live` (S8-04) and hands the answer to every tile. The test that pins this initially passed against a hard-coded host, because the script answered with the same string the hard-code used — the script now answers `http://media.example:1984`, a host only the server could know.

**Simplification made during mutation checking.** A `status === 503` branch on the settings call rendered exactly what the generic failure path renders — the server's own sentence, and no players started. S8-04's whole point was that the server names the problem in words the operator can act on ("GO2RTC_PUBLIC_URL is not configured, so this installation has no media host to name"); a client-side status-code branch that restates it is the duplication that card argued against. The branch is gone; one failure path repeats the server's words.

**`addIceCandidate` before the remote description throws in a real browser**, so candidates that arrive early wait in a queue and are flushed when the answer lands. The null candidate that ends trickle is not sent — go2rtc accepts it, but it is not a value worth putting on the wire as a candidate.

**The slug is checked against the server's own rule** (`server/models/camera.go`: `^[a-z0-9][a-z0-9-]{1,31}$`), because the slug *is* the stream name and it goes into a query string — a slug with a slash would ask go2rtc for a different stream and the tile would show someone else's picture.

**Not mounted anywhere.** `main.tsx` still renders the scaffold's notice; routes and role-aware nav are S8-09's card, and a page mounted into an empty frame would be the spinner the plan forbids. `LivePage` is exported and tested directly, as `LoginPage` and `AuthCallbackPage` are.
