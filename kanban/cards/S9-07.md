# S9-07 — /health + /api/healthz with detector heartbeat (fresh/stale)

## Deliverable

Detector POSTs `/api/internal/v1/heartbeat` `{uptime_seconds}` every 30 s;
server stores `settings.detector_heartbeat_at`; `GET /api/healthz` answers
detector fresh (< 90 s) or stale. `/health` stays DB-free.

## Exit criteria

- [x] fresh/stale boundary asserted at 90 s
- [x] a detector that never reported answers stale (not ok, not an error)
- [x] /health never touches the DB (a healthcheck must not restart a recording server)

## Verification

`docker run --rm -v $PWD/server:/src -w /src golang:1.26 go test ./api -count=1 -run Health`

## Observed

**Observed** 2026-11-06 — `go test ./api -count=1 -run Health` ok (6 tests);
`go test ./... -count=1` all ok; detector fast suite 125 passed in-image.
Live dev stack: after real beats from the running worker,
`GET :8080/api/healthz` → `{"detector":{"age_seconds":14.4,"status":"fresh",
"window_seconds":90},"status":"ok"}`; `docker stop nvr-detector` + 95 s →
`age_seconds":116.3,"status":"stale"` with `"status":"degraded"` and HTTP 200;
`docker start` → fresh again 2.7 s later (the first beat goes out immediately).
`docker stop nvr-postgres` → `GET /health` still 200. Gates: no token 401,
wrong token 401, empty `WORKER_TOKEN` 403 "internal api disabled", bad body 400.

The boundary is asserted on both sides in Go (`SetClock`: 89.9 s fresh,
90.0 s stale — the window is `< 90 s`, so a beat that has aged the whole
window has missed its next one). "Never touches the DB" is structural:
`Handlers.Health` takes no store, and the test closes the underlying
`*sql.DB` before asking `/health`. The never-reported answer is
`degraded`/`stale` with `last_seen: null` — a 200, because the server itself
is fine and restarting it would replace one dead thing with two.

The beat lives in `pipeline.Worker.run` — the loop the shipped binary runs —
not `ServerClient.run`, which only tests use. The first wiring went into the
client loop and the live stack proved it: detector healthy for four minutes,
healthz still `stale`. P-12's failure class, committed by me and caught by the
live check, which is why the live check exists.

Mutation evidence — each break kills its criterion, restore re-green:

| Mutation | Observed failure |
| --- | --- |
| beat wired into `ServerClient.run` (fixture loop) | live healthz stayed `stale` with a healthy 4-min-old detector — the shipped loop never sent it |
| heartbeat without/with wrong token | 401; empty `WORKER_TOKEN` → 403, the documented "internal api disabled" |
| heartbeat body `{}` or negative uptime | 400 — the shape is validated, then the value is not stored (the receipt stamp is the server's clock) |
| (negative) `docker stop nvr-postgres` | `/health` still 200 — the criterion is that this does NOT fail |

Also pinned in `router_test.go` (package main): the production router mounts
`/health` and answers a fresh install's healthz as degraded/stale — the P-12
pattern, so a fixture-only mount cannot ship again.
