## Notes

**Observed** 2026-11-06 — `cd web && npm run typecheck && npm run test:run`:
`tsc --noEmit` clean, `Test Files 9 passed (9)`, `Tests 130 passed (130)` (the
full transcript is in Verification above). Six mutations, each reverted, each
failing exactly the test that claims the behaviour (table above).

**The plan's `<video src="/api/v1/events/:id/clip">` cannot work, and the reason
is the server's own rule.** `server/api/handlers.go`: *"The bearer header is the
only REST credential. `?token=` is accepted on the WebSocket"* — nowhere else. A
browser attaches no header to a subresource, so an `<img>` or `<video>` pointed
at a media route is answered **401 by its own server**. `web/src/api/media.ts`
fetches the bytes through `api/client.ts` (bearer, single-flight renewal) and
hands the element an object URL.

That costs the browser's HTTP cache and buys the criterion. Because the page
fetches the bytes, it can read the 404's body, so a missing clip renders the
server's own sentence — `clip not available` — and never the browser's
broken-player icon. `media.ts` also holds one entry per path with the in-flight
promise, so twenty cards asking for one picture cause one request; the server
says a picture is "written once and never rewritten" (`Cache-Control: private,
max-age=3600`), so holding it for the tab honours a fact the response already
states. A `failed` read is forgotten, so a tier that was briefly unreachable does
not stay unreachable for the tab.

**The address bar is the filter state, in the server's parameter names.**
`?camera_id=&from=&to=&class=&zone_id=&severity=&q=` is exactly what `ListEvents`
reads, so the page holds no filter state: it reads the query, asks for that, and
writes the query. Clicking a card's class chip sets `class=`, a zone chip sets
`zone_id=` (from `zone_ids`, because a name can be reused and an id cannot), the
picker sets `camera_id=`, and each active filter renders as a chip whose ×
removes only that key. `filtersFromParams`/`filtersToParams` live in
`web/src/api/events.ts` so the wall and the drawer cannot invent two mappings.

**Severity stays a number.** `server/models/event.go`: *"A number, not a word, so
a filter is a comparison and the web hook payload says the same thing the console
draws."* So the ring shows 1/2/3 in the theme's `--severity-N`, and the console
invents no adjective for it. The ring's classes are written out in full rather
than interpolated — Tailwind reads source text, and a `border-severity-${n}` it
cannot see is a ring that arrives uncoloured, quietly, on the one element whose
job is to be seen.

**The feed keeps the cards current and does not decide what is on the page.**
`mergeLive` (one copy, in `api/events.ts`) overlays the store's frame on the row
the server answered; S6-08 sends the whole `eventView` on all three frames, so a
frame is a newer answer about the same row, not a partial patch — and
`realtime.ts` says it keeps the payload loose "for the event UI to type", which
is this. **Rejected — prepending an event that arrived after the fetch**: the
store accumulates every event the tab has ever seen, so "new since this read" is
not derivable from it without comparing the server's clock to the browser's,
which is the one comparison this product refuses. The page states what it loaded
and whether the server said `truncated`.

**The row's flags are claims; the routes are the truth.** `has_clip: false` asks
for nothing and says `clip not available` — the same sentence the route would
have answered, because the server draws no distinction between "never cut" and
"aged out on both sides" either. `has_clip: true` asks, and the answer decides:
404 → the server's sentence, 502 → the tier's, 200 → a player. The test pins the
middle case, which is the one a naive implementation gets wrong.

**A recorded box is a pixel, and pixels need a frame.** The worker sends
`[x1,y1,x2,y2]` in the detection frame's pixels and the server stores them
verbatim; the event view carries no frame size. The drawer borrows
`detection_width`/`detection_height` from the camera row — and those default to
**0**, in which case the installation fell back to a server-side value the
console is not told. Then the drawer draws **no** boxes, states the count, and
says it will not guess where they land: a box placed by a guess looks exactly
like evidence. Filed as **P-10** — the fix belongs on the server, and the zone
polygons show the way (they are validated into `0..1` on write, which is why a
zone always draws and a box never does on a default camera).

**The strip is the event's own window, and says so.** It is drawn on the
`from`/`to` the **server echoed**, never this browser's clock, and the caption
states that the clip may reach past it because the roll settings are not exposed.
Filed as **P-11**, with S8-08's retention panel named as the second consumer of
whatever route wins.

**Two files became four.** `api/events.ts` (the server's shapes + the URL↔query
mapping) and `api/media.ts` (bearer-protected bytes) exist because the wall and
the drawer need both and must not disagree about either. The card named two
paths; the extra two are one home each for a rule both pages would otherwise
copy.

**The drawer is a URL, not a modal state.** `EventsPage` reads
`useMatch('/events/:id')` — matched against the location, not the route table —
so the drawer is deep-linkable and closing it returns to `/events` with the
filters intact. **S8-09 must mount `EventsPage` at both `/events` and
`/events/:id`**, which is what the plan's route list already says.

**Drive-by, found while matching the theme:** `LivePage` (S8-05) used
`bg-surface`, `border-border` and `text-danger` — three classes that are not in
`tailwind.config.ts`, so they generated nothing and the wall rendered without its
surface, rule or error colour. Now `bg-bg-card`, `border-rule`,
`text-status-error`. Its local `serverWords` also moved to `api/client.ts`
rather than being copied a second time.

**Not here:** the delete button (admin-only, and role-gated nav is S8-09), the
zone overlay's edit affordances (S8-07's editor), and i18n wiring — every string
is English inline, as the plan scopes v1.
