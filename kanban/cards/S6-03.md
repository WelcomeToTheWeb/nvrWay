# S6-03 — Event upsert semantics: open/extend/close on the server clock

## Deliverable

open inserts (StartedAt = EndedAt = ts, Open = true); extend advances EndedAt, appends objects capped at 200 oldest-first, unions classes/zones/rules, takes max severity; close sets Open=false + final EndedAt. ts is time.Now().UTC() at receipt.

## Exit criteria

- [x] one event across 3 signals (event_key dedupe)
- [x] objects capped at 200, trimmed oldest-first
- [x] severity monotone max
- [x] post-close extend answers 200 with "event closed" and mutates nothing
- [x] a signal with a future ts never produces started_at > now()

## Verification

`docker run --rm -v $PWD/server:/src -w /src golang:1.26 go test ./store -count=1 -run Upsert`

## Notes

Audit of code that already exists: store/events.go has UpsertByEventKey (verified 2026-11-01). Check each of the five rules against it and file the test file.

**Package deviation (2026-11-01).** The seeded card named `server/media/` for the test
file and `./media` for the verification command. There is no `media` package: the
state machine lives on `store.EventStore` (`server/store/events.go`), so its tests
are `server/store/events_test.go` (package `store`), where the fixture helpers
(`newTestStore`, `seedCamera`) already are. Paths and Verification re-pointed at
`./store`; the deliverable is unchanged.

**The 200 half of criterion 4 belongs to S5-10.** The store answers `ErrEventClosed`
with the closed row attached, which is exactly what the internal-API handler needs
to answer `200 {"error":"event closed"}` without a second read; there is no handler
to test in this card (the signals intake is S5-10, still in the backlog). Proven
here: the error is `ErrEventClosed`, the row is returned, `created` is false, and
before/after reloads are byte-identical on `ended_at`, `severity`, `classes_json`,
`signal_count`, `open`.

Test file: 11 Upsert tests already covered open/extend/close, replayed open and
extend, the 200-box cap trimmed oldest-first (50 oldest dropped, newest kept), the
server clock (future ts and zero ts), close-without-open, unknown action. Two exit
criteria had no test of their own and were added:
`TestUpsertOneEventAcrossThreeSignals` (open + extend + close on one key → 1 row,
`signal_count` 3, window start = the open's ts, closed) and
`TestUpsertSeverityIsAMonotoneMax` (severity 4 stays 4 under a severity-2 extend,
rises to 5).
