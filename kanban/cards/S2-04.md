**Deviation from the port, recorded:** the comment in `jwks.go` promises "an
unknown `kid` triggers a single refresh; a second miss for the same `kid` is
refused", but OurWay's code refreshes on *every* verification with an unknown
kid — a login loop against an IdP that does not publish the key the token names
costs one extra fetch per attempt, not one. nvrWay keeps the promise:
`JWKSClient` remembers the kid ids it searched for (`misses`), refuses a repeat
miss on the spot, and clears the memory when the kid turns up. The test counts
the GETs: 1 warm fetch, +1 for a rotation to a newly published `k2`, +1 for the
first ghost `kid`, and 0 for five repeats.

No SAML: `saml.go`, `saml_test.go`, `testsaml/`, `capture_vendor_saml_test.go`
were not copied, and `models.SSOProvider` has no SAML column set.
