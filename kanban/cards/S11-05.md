# S11-05 — Coverage ratchet recorded (coverage.sh --record)

## Deliverable

Baseline recorded once at the end of Step 9 (plan) and ratcheted up from there, never down.

## Exit criteria

- [x] coverage.baseline.json holds real numbers, not 0.0
- [x] CI fails when coverage drops below the baseline
- [x] the detector is measured with pytest --cov

## Observed

**Observed** 2026-11-07 — `scripts/coverage.sh --record`: exit 0,
`coverage: recorded baseline server=77.4 detector=92 web=89.72`;
`coverage.baseline.json` now `{"server": 77.4, "detector": 92.0, "web": 89.72}`.
The three measurements are the script's own: `go test ./... -coverprofile`
total, `python -m pytest -m "not slow" -q --cov=nvr_detector --cov-report=term`
TOTAL (inside the detector image, pytest-cov into /tmp/pcov — the criterion's
pytest --cov), and vitest json-summary. CI runs the same script ungated:
build.yml's "Coverage ratchet" step (`bash scripts/coverage.sh`) is behind
`needs.preflight.outputs.harness == 'true'`, and the preflight probe
(grep for `skeleton, card S0-04` in scripts/*.sh) answers true — the marker
left with S9-08.

| baseline `web: 89.72` → `95.0`, `scripts/coverage.sh` (no flag) | rc=1: `coverage: web fell below the baseline: 89.72% < 95.0%` + `the ratchet only turns one way` — the CI step runs this exact command, so a real drop reddens the job |

## Deviations

The plan said "recorded at the end of Step 9"; the recording happens at
Step 11's close because the floor is only worth freezing once S11-01/02/03
added their tests — a Step 9 floor would have been a lower number the very
next card had to explain away.

The first `--record` measured web at 85.7%: the v8 coverage provider's
default include is every `.ts` in the package, so the Playwright specs in
`e2e/` counted as 0% and the floor would have punished adding browser tests.
Fixed in vite.config.ts (`coverage.include: ['src/**']` — the unit
denominator is src/ only) and re-recorded: 89.72%.
