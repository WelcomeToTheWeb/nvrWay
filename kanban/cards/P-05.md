# P-05 — Track server/models: .gitignore's models/ pattern ignored a Go package

## Deliverable

The plan's Step 0 line says .gitignore adds `models/`, meaning the detector's ONNX export directory. Unanchored, the pattern also matched `server/models/`, so the entire Step 1 models package (18 files) was never committed: the pushed tree cannot build, because every `nvr/server/models` import resolves to nothing. Anchor the artifact pattern to the repo root (`/models/`, `*.onnx`) and commit the package.

## Exit criteria

- [x] server/models/*.go tracked (18 files: 14 models + json helpers + 3 test files)
- [x] the detector model directory stays ignored (`/models/`, `*.onnx`)
- [x] a fresh clone builds: go build ./... and go test ./... exit 0 on the tracked tree

## Verification

`git ls-files server/models | wc -l && git clone --quiet $PWD /tmp/nvrclone && cd /tmp/nvrclone/server && go build ./...`

## Notes

Found while staging Step 2 (2026-11-01): `git add server/models` answered "paths
are ignored by one of your .gitignore files". `git ls-files server/models | wc -l`
answered **0** — nothing in the package was tracked — while `git status
--ignored -s` listed `!! server/models/`.

S1-03 through S1-07 are Done with green suite output quoted on the cards. That
evidence holds: the code exists and the suite passed. What was missing is that
none of it was ever in git, so Step 1's Done cards described a tree only this
working copy had. `go build ./...` is green here and would fail on a fresh clone.

Fixed in `.gitignore`: the artifact pattern is anchored to the repo root
(`/models/`, `server/models/` is now tracked), the `*.onnx` line stays, and the
comment names the anchoring so the next person who touches the file knows why the
pattern has a leading slash.

Observed 2026-11-01: `git ls-files server/models | wc -l` -> **18** (14 model
files, `json.go`, `camera_test.go`, `helpers_test.go`, `models_test.go`);
`git status --ignored -s` lists no `server/models` entry; a fresh clone
(`git clone /root/projects/nvrWay`) builds and tests green in golang:1.26 —

`ok nvr/server/config`, `ok nvr/server/models`, `ok nvr/server/store`.
