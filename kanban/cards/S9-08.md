## Deviations (deliberate, each with a reason)

- **`NVR_E2E=1` is exported to the server but no server code reads it.** The plan names it; nothing consumes it. The throwaway-ness is structural (sqlite + media dirs under /tmp, private ports, per-run secrets), not a mode switch, and inventing a hook with no consumer is the decoration this repo has twice called out (P-12 class). The script header says so. `NVR_E2E_RUN_ID` is real: it scopes the seeded camera's slug (`e2e-<runid>`) and is exported to the specs.
- **The e2e stack runs its own go2rtc container** (`nvr-e2e-go2rtc`, 127.0.0.1:1985/18554/18555, own config volume). The plan did not name one, but a camera POST without a sidecar answers 502 (`camera saved, go2rtc config not applied`) — the specs could not create a camera. The script restarts the container once after seeding because streams instantiate at go2rtc boot (S3-07) and the e2e stack has no compose project for the server's restarter to drive (`GO2RTC_COMPOSE_FILE` unset → Noop, which is what keeps camera writes at 201).
- **`go build` + run the binary, not `go run`.** `go run` puts the compiled child behind the wrapper: killing the recorded pid orphans the server. The state file's pid is the server itself.
- **The e2e camera is `record_mode: off` with a `testsrc` exec source.** The host has no ffmpeg (the recorder would crash-loop), and testsrc renders inside go2rtc's own bundled ffmpeg — no mounted files, and a moving picture keeps liveness honest.
- **coverage.sh installs `pytest-cov` and `onnx` into the throwaway detector container** (`--target=/tmp/pcov`). Production does not measure itself, and `onnx` is only a test-fixture builder; S11-02 tracks making the suite green in the image without the runtime install.
- **`test` exits non-zero until S8-12 lands the specs** — the harness is done; the suite is the other card. S11-04 turns it green.

## Notes

The harness is the product's acceptance surface: these names are already promised in README.

**Two host facts found in Step 8 that `e2e-stack.sh` must respect** (observed 2026-11-05, S8-01/S8-02 cards carry the evidence):

- `vite preview` binds `[::1]` only by default — `curl http://localhost:3113/` answers 200 while `curl http://127.0.0.1:3113/` fails to connect. So the script must either start preview with `--host 127.0.0.1` (or `0.0.0.0`) or reach it over the hostname `localhost`. If it hard-codes `127.0.0.1` the Playwright suite cannot connect, and the failure reads like a broken console rather than an address-family mismatch.
- The host is Node v26.13.0 / npm 11.20.0, not the Node 22 / npm 9 the plan assumed. npm 11 gates install scripts (`esbuild` postinstall is not run and the build is still fine — do not "fix" the warning), and Node 26's experimental webstorage shadows jsdom's `localStorage` in the vitest suite (shimmed in `web/src/test/setup.ts`). CI's `ubuntu-latest` runner may differ; `npm ci` output there should be read, not assumed.
