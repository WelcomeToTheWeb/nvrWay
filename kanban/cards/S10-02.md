## Observed

**Observed** 2026-11-07 — `scripts/dev.sh --demo` (rc=0): login → camera
`demo-doorbell` → zones (porch loiter dwell=4 severity=3) → fs `local-tier`
default → go2rtc restart → `demo: probe online — exec:ffmpeg -re -loop 1 -i
/fixtures/bus.jpg …`. The plan's "exec: and ffmpeg:" arrive as one producer
whose source is `exec:ffmpeg …` — go2rtc reports the exec producer, whose
binary is ffmpeg; there is no second `ffmpeg:`-scheme producer for this
shape, and the seeder asserts `online && "exec:" && "ffmpeg"`. The
no-physical-camera proof completed: `GET /api/v1/events` returned
`demo-doorbell / porch / loiter / severity 3 / classes ["person"] / 226
signals` — the whole chain (fixture → go2rtc tap → detector → zone rule →
event row) ran on the fixture. Detector boot log: `go2rtc=http://go2rtc:1984
auth=on`. Detector suite: 128 passed (+3 auth tests), 2 deselected.

Two live-stack findings the seeder now encodes:

1. **The sidecar needs a restart to run a pushed config.** The camera write
   pushes `/api/config` and go2rtc persists it, but streams instantiate at
   boot only (S9-04's finding, re-proved: `/api/streams` was `{}` with the
   streams already in `/config/go2rtc.yaml`). The server's Compose restarter
   is Noop in dev (no docker socket in the server container), so dev.sh —
   which is the operator here — runs `compose restart go2rtc` after seeding.
2. **The motion gate starves a static loop in continuous mode.** 422 frames,
   1 inferred, 0 events: a looped JPEG never moves the 160-px thumbnail 1%,
   and the gate is right to skip. The demo camera is `record_mode: events`
   (gate off — "an events camera's frames *are* the trigger"), and the seeder
   reconciles an older continuous camera to events on the next run.
