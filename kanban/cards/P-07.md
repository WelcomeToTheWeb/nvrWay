# P-07 — Ignore the Hindsight artifacts the memory tool drops in the repo root

## Deliverable

Two files the coding-agent memory tooling writes into the repo root — nvr_cfg2.json (the bank's config dump) and spec.json (the Hindsight HTTP API OpenAPI spec) — sit untracked and unignored, so every git status shows them and a `git add -A` would commit a tool's config into the product. Ignore them with patterns anchored to the repo root, and prove no source path is caught by them.

## Exit criteria

- [x] `/nvr_cfg2.json` and `/spec.json` are ignored (git check-ignore names the pattern)
- [x] the patterns are root-anchored with a leading slash, per P-05: an unanchored `spec.json` would also ignore a real spec file in any package
- [x] nothing under server/, kanban/, docs/, web/, scripts/ became ignored: git status --ignored -s shows only the two artifacts and the known artifact directories
- [x] git status --porcelain is empty on a clean tree

## Verification

`git check-ignore -v nvr_cfg2.json spec.json && git status --porcelain`

## Notes

Observed 2026-11-02 while committing S2-04: `git status --short` listed `?? nvr_cfg2.json` and `?? spec.json`. They are this machine's memory tooling's own files (the bank config, and the API spec it fetched), not project files — the repo has no OpenAPI document at its root, and its deployment config is .env / docker/, not a bank config.

The patterns are anchored (`.gitignore:39:/nvr_cfg2.json`, `.gitignore:40:/spec.json`) for the reason P-05 recorded: an unanchored `spec.json` matches at any depth, and the repo has source directories whose names are not reserved (`server/models/` is a Go package, and it was the unanchored `models/` pattern that kept it out of git).

Closed 2026-11-02 -> EXIT=0:

```
$ git check-ignore -v nvr_cfg2.json spec.json
.gitignore:39:/nvr_cfg2.json	nvr_cfg2.json
.gitignore:40:/spec.json	spec.json
$ git status --porcelain
 M .gitignore
 M KANBAN.md
 M kanban/seed.py
?? kanban/cards/P-07.md
$ git status --ignored -s
!! kanban/__pycache__/
!! nvr_cfg2.json
!! spec.json
$ git check-ignore -v server/sso/spec.json web/src/spec.json kanban/nvr_cfg2.json docs/spec.json ; echo $?
1
```

The last command is the anchoring proof: a file named `spec.json` in a package is **not** ignored (exit 1 = no pattern matched), and the ignored set gained only the two artifacts. The porcelain list above is the tree at commit time; after this commit it is empty.
