# Agent Note: console-shell-routes-feed-lifecycle-audit-read

Status: implemented

## Problem

Every console page shipped before the shell existed deferred three things to it, and none of them are visible from any single page: the event drawer and camera editor are `useMatch` reads that silently never render if the route table does not mount their page twice; `LivePage` calls `connect()` and deliberately never `disconnect()`, so a console that mounts no wall has no feed and a logout leaves a socket streaming; and the audit ledger (S2-08) had no read route at all, so "who did what, and did the server refuse" had no answer.

## Decision

`web/src/App.tsx` is the shell: it owns the route table, the auth guard, the role-aware nav, the live-feed lifecycle, and the stale/refused banner. The route table mounts `EventsPage` at both `/events` and `/events/:id` and `CamerasPage` at both `/cameras` and `/cameras/:id` — the drawer/editor are URLs, and `App.test.tsx` pins each pairing with a fresh render at the deep URL (a reload is a fresh render). The signed-out guard keeps `/login` and `/auth/callback` reachable and `Navigate`s everything else to `/login`; an authenticated visit to `/login` redirects to `/live`. The nav renders Settings and Audit only for `hasRole('admin')`; there is deliberately NO route-level role wrapper — the pages refuse deep links themselves (SettingsPage, AuditPage draw the refusal before any request) and the server's `RequireRole(admin)` is the gate. The shell's effect calls `useRealtime.getState().connect()` when `isAuthenticated` and `disconnect()` when it turns false or the shell unmounts; `connect()` is idempotent so `LivePage`'s own call costs nothing. `FeedBanner` renders the store's `status`/`reason` verbatim for `stale` (role=status) and `refused` (role=alert) and nothing when the feed is current. `main.tsx` mounts `BrowserRouter > AuthProvider > App` — the router lives outside `App` so suites mount the shell under `MemoryRouter`. Server side: `GET /api/audit` (`server/api/audit.go`, admin group) with filters `actor`/`action`/`target_id`/`outcome`/`from`/`to`/`limit`/`offset`, a `limit+1` probe row so `truncated` is a fact, and `{audits, count, limit, offset, truncated}` newest-first; `details` is parsed to a map server-side, null when unparseable or absent. The ledger read is NOT audited.
## Alternatives considered

Route-level `RequireRole` wrappers in the client — rejected: a third copy of the same sentence (nav hiding, page refusal, server gate already exist), and a wrapper that drifts from the server's vocabulary is a lie with a redirect. Offset in component state for AuditPage paging — rejected: putting `offset` in the URL makes paging deep-linkable and makes the filter-change page reset free (rewriting params without offset IS the reset), and it removed a two-effect state dance that double-fetched. Auditing the ledger read — rejected: `models/audit.go` declares no read verb ("a handler cannot invent a verb"), and a read that writes rows moves the page count under the operator reading it; the recursion argument is in audit.go's header comment. Per-keystroke filter requests — rejected: the URL is the filter state (the event wall's rule), and a request per character on a 365-day ledger is self-denial; the filter bar submits.
## Consequences

Bought: the console is now one navigable app — deep links, reloads, back button, and pasteable filtered ledgers all work, and the feed survives page changes while dying with the session. Cost: `App.test.tsx` must script every page's reads behind the shell (the harness `server()` grew with it); the nav's role list is a second place role-gating is expressed (kept honest by the viewer-nav mutation test). Follow-up: S8-12's Playwright specs should walk the same deep links against a real server; if a future page needs a non-admin settings view, the nav gate and the page refusal must move together.
