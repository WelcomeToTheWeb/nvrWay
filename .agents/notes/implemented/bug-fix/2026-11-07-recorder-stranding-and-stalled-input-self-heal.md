# Agent Note: recorder-stranding-and-stalled-input-self-heal

Status: implemented

## Problem

verify.sh run 5 lost the demo camera mid-run: segments stopped at 03:48:56 and never resumed while event signals kept arriving, and the recorder logged nothing. The chain: go2rtc's exec producer died mid-stream → the recorder's ffmpeg blocked on the RTSP read forever (no socket timeout) → the tail ticker stopped it at window close → cameraLoop returned via the silent `!wantsRecording` path → the stale run entry stayed in `r.runs` → reconcile skips cameras that already have a run → the next signal's OpenWindow+nudge found "already running" for a loop that owned nothing, forever (SIGQUIT goroutine dump: no cameraLoop/tailSegments goroutine existed). The tile stayed green; recording was dead.

## Decision

Two independent fixes in the recorder, each pinned by a test. (1) Stranding: the goroutine `startRunLocked` spawns now calls `r.cameraLoop(runCtx, run)` and then, under `r.mu`, deletes its own map entry guarded by identity (`if r.runs[cam.ID] == run { delete(r.runs, cam.ID) }`) — the identity check means a run never deletes its successor's entry. `TestWindowReopenRespawnsASilentExitLoop` sets `PollInterval` to 10 s so the reopen's nudge is the only reconcile pass (the field shape: PollInterval 10 s, signals every few seconds), closes the window, waits for the child to end, reopens, and requires a new spawn; with the delete reverted the test FAILs. (2) Stall: the RTSP input argv gains `-timeout 10000000` (µs) — verified against the image's ffmpeg 6.1.1 by SIGSTOP-ing go2rtc's exec producer under a connected recorder: ffmpeg answers "Operation timed out" and exits within ~10 s, the supervisor logs the exit and restarts (gen 29 → 30, segments resumed). Because a child could still hang without exiting, `tailSegments` also carries a stall watchdog: `lastSegment` (advanced on every recorded segment, seeded at spawn) is checked on the tail's own tick, and silence beyond `stallLimit()` = 3×SegmentSeconds+10 s logs "no segment for … the input is stalled", stops the child, and returns `errStalledInput` — which the cameraLoop treats as a crash (log, offline tile, backoff, restart), unlike `errWindowClosed` which stays silent. `TestStalledInputIsRestarted` (continuous camera, fake clock advanced past the limit) FAILs with the threshold multiplied by 1000.
## Alternatives considered

Making reconcile detect dead runs (a liveness flag on run, checked in the poll pass) lost: the loop deleting its own entry on the way out is the same guarantee with no new state and no new race — reconcile's "skip if a run exists" stays correct because the entry now cannot outlive its loop. Widening reconcile to stop-and-replace stale entries lost for the same reason plus it would fight the identity problem (which run owns the entry). For the stall, `-rw_timeout 10000000` lost on observation: the image's ffmpeg 6.1.1 rejects it on an rtsp input ("Option rw_timeout not found") — it is an AVIOContext option the rtsp demuxer does not expose. Relying on `-timeout` alone lost: it provably cuts the observed stall, but a child hung in a state ffmpeg does not notice would still strand the camera silently, and the watchdog costs one timestamp and one comparison in a ticker that already runs.
## Consequences

The recorder self-heals both failure shapes: a dead input becomes a logged exit + restart within ~10 s (ffmpeg) or ~3 segments (watchdog), and a silent loop exit can never strand a camera. Cost: the watchdog must not fire on legitimate silence — safe today because a running child with an open window always produces segments at SegmentSeconds cadence; a future source that legitimately goes silent (e.g. a doorbell camera with no one at the door in events mode) would need the window check to gate the watchdog, which it already does for events cameras (closed window returns before the stall check). The go2rtc-side root cause of the original producer death was not diagnosed — the fixes make the system self-heal regardless; if producer deaths recur, go2rtc's own logs are the next place to look.
