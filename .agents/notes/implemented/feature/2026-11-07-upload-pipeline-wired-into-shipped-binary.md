# Agent Note: upload-pipeline-wired-into-shipped-binary

Status: implemented

## Problem

The uploader (S7-08), sweeper (S7-09) and queue (S1-04) were built and unit-tested, but verify.sh gate 7 found the upload tier empty in the live stack: `storage.NewUploader` and `sweeper.New` had zero callers in main.go, and no production code path ever enqueued an upload job. Each suite seeded its own queue, so the P-12 failure class (component built, tested against its own fixture, never wired into the shipped binary) recurred a third time. On top of that, the first real Postgres exercise rejected every clip/snapshot job: `storage_jobs.id` was a uuid column and `<event_id>:clip` is not a uuid (P-08, SQLSTATE 22P02) — sqlite had never enforced it.

## Decision

`Store.EnqueueUpload(kind, jobID, localPath)` is the single enqueue path: it resolves the default backend (no backend → skip silently, (false, nil)), and enqueues `JobInput{ID: jobID, Kind, Target: localPath, BackendID, Action: upload}`. Three production call sites: `media/segments.go recordSegment` (job id = segment id), `media/clips.go` after assemble (id = `store.EventJobID(ev.ID, JobKindClip)`), `api/detector_api.go writeEventSnapshot` (id = `store.EventJobID(eventID, JobKindSnapshot)`). `store.EventJobID(eventID, kind)` is the one naming helper for event media jobs (`<event_id>:clip` / `<event_id>:snapshot`); all six writers — camera purge ×2, event purge ×2, clip builder, snapshot writer — call it, and `storage.eventIDFromJobID` is the reader of the same contract. Migration v2 (`store/migrate.go migration storage_jobs_id_is_text`) runs `ALTER TABLE storage_jobs ALTER COLUMN id TYPE text` guarded to the postgres dialect and records a no-op on sqlite so the ledger has the same shape everywhere; the model tag is `type:text`. main.go constructs the uploader (WorkerID `hostname:pid`, Tick `UPLOADER_TICK_SECONDS`, `Sources: &storage.SourceRows{...}`) and the sweeper (Config from retention settings, broadcast adapter `sweeperBroadcast` publishing `storage.queue` through the API hub — nil-safe when the hub is nil) before the HTTP server starts, each with a boot log line. `SourceRows.MarkSourceUploaded` writes the upload mark onto the owning row (segment → Segments.MarkUploaded; clip → Events.MarkClipUploaded; snapshot → MarkSnapshotUploaded) after `jobs.MarkUploaded`; a mark failure retries the whole job (re-put is safe, the key is deterministic). Negative guarantees: EnqueueUpload never creates a backend, never queues when none exists; the uploader never deletes the local file; the sweeper's un-uploaded protection reads the marks SourceRows writes.
## Alternatives considered

UUIDv5 of `"<event_id>:clip"` for the job id (keeps the column a uuid) lost because every debug read would require deriving the hash and the uploader already parses the suffix back out to find the event row — the suffix would live in the value anyway. A uuid surrogate + `object_key text unique` column lost because every GetByID caller (queue view, requeue route, uploader claim/mark) changes to buy nothing the widened key gives. Enqueueing from the sweeper (scan for un-uploaded rows and queue them lazily) lost because enqueue-at-production makes the queue the complete ledger of owed objects; a scan would race the sweeper's own deletion window.
## Consequences

The queue is now the honest ledger: gate 7 can assert "queue reached uploaded" and the sweeper's un-uploaded protection has real marks to read. Cost: three more production call sites that a future media path must not forget (mitigated: they all go through one helper). The migration is irreversible on Postgres in the sense that text ids may exist afterward — a downgrade would need to delete non-uuid rows. Follow-up: S11-01's suite-green pass now covers store+storage+media together; the compose note "one server instance only" is load-bearing for the sweeper/uploader single-writer assumption.
