# Agent Note: events-wall-and-drawer

Status: implemented

## Problem

Steps 1–7 made the server answer "what happened": the event list with its seven filters, the detail with its recorded boxes, the snapshot and clip routes, the WS fan-out. Nothing in the console showed any of it, so an operator could not see an event, could not narrow to the one they were looking for, and — the failure that matters for a product whose whole promise is proof — could not tell an event with no footage from a page that had not finished loading.

## Decision

`web/src/pages/EventsPage.tsx` and `web/src/pages/EventDetail.tsx` ship the event wall and its drawer, with two shared modules behind them: `web/src/api/events.ts` (the server's `eventView`/`segmentView` shapes plus the one URL↔query mapping) and `web/src/api/media.ts` (bearer-protected bytes).

**Media is fetched, never pointed at.** `server/api/handlers.go`: "The bearer header is the only REST credential. `?token=` is accepted on the WebSocket" — nowhere else — so an `<img>`/`<video>` aimed at `/api/v1/events/:id/{snapshot,clip}` is answered 401 by its own server. `useMediaUrl(path)` fetches through `api/client.ts` with `responseType: 'blob'` and hands the element an object URL, and returns one of `none | reading | ready | absent | failed`. `absent` is a 404 and carries the server's own `{"error": …}` sentence, read out of a Blob body; `failed` is everything else. A module-level map holds the in-flight promise per path, so twenty cards asking for one picture cause one request, and a `failed` entry is evicted so a briefly unreachable tier does not stay unreachable for the tab. `has_snapshot: false` / `has_clip: false` pass `null` and ask for nothing.

**The address bar is the filter state, in the server's parameter names.** `?camera_id=&from=&to=&class=&zone_id=&severity=&q=` — exactly what `ListEvents` reads. The page holds no filter state of its own; `filtersFromParams`/`filtersToParams`/`activeFilters` in `api/events.ts` are the only mapping, and a card's class chip writes `class=`, its zone chip writes `zone_id=` from `zone_ids` (never from the name — a name can be reused, an id cannot), the picker writes `camera_id=`. The camera list is fetched so a chip can say `camera: porch` instead of a uuid, and falls back to the id when the list is unreadable.

**The feed updates rows; it does not choose them.** `mergeLive(event, live)` in `api/events.ts` overlays a frame on the fetched row — one copy, because the wall and the drawer must not disagree about what a frame means. It is sound because S6-08 sends the whole `eventView` on all three event types, and `realtime.ts` states that it keeps the payload loose "for the event UI to type".

**The drawer is a URL.** `EventsPage` reads `useMatch('/events/:id')` — matched against the location, not the route table — and renders `EventDetail` when it matches; closing navigates to `/events` with the query preserved. S8-09 must mount `EventsPage` at both `/events` and `/events/:id` (recorded on that card).

**Two refusals are the shipped behaviour, not TODOs.** A recorded box is `[x1,y1,x2,y2]` in the detection frame's pixels (`Detection.as_object()` in `detector/nvr_detector/model.py`, stored verbatim by `api/detector_api.go`) and the event view carries no frame size, so the drawer borrows `detection_width`/`detection_height` from the camera row; when those are 0 — the default — it draws no boxes, states the count, and names the reason. Zone polygons, validated into `0..1` on write, always draw. Filed as P-10. The segment strip is drawn on the `from`/`to` the **server echoed** and captions that the clip may reach past it, because `PRE_ROLL_SECONDS`/`POST_ROLL_SECONDS` are not exposed to the console; filed as P-11.

Severity is drawn as the number 1/2/3 in `--severity-N`, because `server/models/event.go` says "A number, not a word". Those classes are written out in full in a lookup map rather than interpolated: Tailwind's scanner reads source text, so `border-severity-${n}` generates nothing and the ring arrives uncoloured.
## Alternatives considered

Pointing `<video src>`/`<img src>` at the media routes — the plan's own markup — was rejected because the server's bearer-only rule answers them 401, and because fetching the bytes is what makes the 404's body readable, which is how "clip not available" becomes the server's sentence rather than a broken-player icon. Prepending events that arrive on the feed after the fetch was rejected: the store accumulates every event the tab has ever seen, so "new since this read" is not derivable without comparing the server's clock to the browser's — the one comparison this product refuses — and a wrong count would read as a quiet property. Padding the segment request by a constant the console invented (30 s, say) was rejected: right on the plan's defaults, wrong on any installation that changed them, and it would look like evidence. Drawing boxes at a guessed frame when `detection_width` is 0 was rejected — a box placed by a guess looks exactly like evidence; the count is stated and the position refused. Normalising the boxes in the console rather than filing P-10 was rejected because the same number is also in the webhook payload, so a console-side fix would split what a row, a payload and a picture all mean. And a second local copy of `serverWords` was rejected in favour of exporting it from `api/client.ts`, which also let `LivePage`'s copy go away.
## Consequences

Bought: the proof surface is on screen — frame, rule, boxes counted, footage band — and every absence on it is named in the server's words; a filter is shareable, reloadable and back-button-able; the media-fetch seam exists once, so S8-07's snapshot-backed zone editor and S8-08's panels inherit the bearer rule instead of rediscovering it.

Costs and obligations: object URLs bypass the HTTP cache and are never revoked, so a tab's memory grows with the media an operator actually looked at — acceptable at 640-wide JPEGs and short clips, and the server's own `max-age=3600` rationale is what the in-module cache honours. Blob playback gives up `Range`/206 seeking for the local case (the remote tier already streams from byte 0, so nothing is worse there); if clips grow long, the answer is a signed short-lived media URL, which is a server card, not a console patch. `EventsPage` fetches a thumbnail per card on the page (up to 200), which is fine on a LAN box and worth a windowing decision if the wall ever renders hundreds. The drawer cannot place recorded boxes on a default camera until P-10 lands, and its strip is narrower than the clip until P-11 does — both are stated on screen, not hidden. i18n stays unwired (English inline), as v1 scopes it.
