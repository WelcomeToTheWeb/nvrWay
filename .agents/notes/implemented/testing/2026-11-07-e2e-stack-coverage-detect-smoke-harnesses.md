# Agent Note: e2e-stack-coverage-detect-smoke-harnesses

Status: implemented

## Problem

Step 11 consumes three harnesses that were S0-04 skeletons: the Playwright suite needs a throwaway stack that cannot touch the dev database (S11-04), the coverage ratchet needs one command over all three suites (S11-05), and the slow model smoke needs to run in the detector image with a skip that cannot pass as success (S11-02). The card also demanded fresh-clone runnability, which exposed that docker/.env.example never existed although dev.sh's error message told you to copy it.

## Decision

scripts/e2e-stack.sh runs a fully private stack: sqlite at `sqlite://$run_dir/nvr.db` plus all media dirs under /tmp/nvr-e2e/<runid>/, the server BUILT (go build, not go run — the recorded pid must be the server itself, since killing a `go run` wrapper orphans the compiled child) on :9090, a `nvr-e2e-go2rtc` container on 127.0.0.1:1985/18554/18555 with its own config volume, one seeded camera `e2e-<runid>` (exec: testsrc source rendered by go2rtc's bundled ffmpeg, record_mode off because the host has no ffmpeg), and `vite preview --host 127.0.0.1 --port 3113` proxying /api and /ws via NVR_PROXY_TARGET (web/vite.config.ts). GO2RTC_COMPOSE_FILE is unset so the server's restarter is Noop — camera writes answer 201 — and the script itself `docker restart`s the sidecar once after seeding, because streams instantiate at go2rtc boot (S3-07). stop_quietly wipes the config volume: go2rtc persists the API-pushed config, and a stale volume carries the previous run's API credentials, which 401-locks the fresh server out of its own sidecar. NVR_E2E=1 is exported but no server code reads it — the throwaway-ness is structural, and the script header says so; NVR_E2E_RUN_ID is real (it scopes the seeded slug and is exported to the specs). scripts/coverage.sh measures server (host go or golang:1.26 fallback; `go tool cover` must run inside the module dir), detector (pytest --cov in the image; pytest-cov and onnx pip-installed into the throwaway container via --target=/tmp/pcov — production does not measure itself, S11-02 tracks the image fix), and web (vitest json-summary), and refuses any number below coverage.baseline.json; --record is S11-05's. scripts/detect-smoke.sh fails a pytest skip: pytest exits 0 on a skip, so the script greps the test's own "smoke ok" line and refuses without it. docker/.env.example now exists with dev credentials committed on purpose, and dev.sh copies it to docker/.env on first run.
## Alternatives considered

Rejected running the e2e stack without a go2rtc sidecar: a camera POST without one answers 502 ("camera saved, go2rtc config not applied"), so the S8-12 specs could never create a camera. Rejected pointing the e2e server at the dev compose's go2rtc: the config push renders the whole desired config from the e2e camera rows and would wipe the dev stack's streams. Rejected an NVR_E2E=1 server-side hook (e.g. skip sidecar apply): no consumer exists, and inventing a mode switch is the decoration this repo has called out twice (P-12 class). Rejected baking pytest-cov/onnx into the detector runtime image: the runtime image is production, and onnx is only a test-fixture builder. Rejected `go run` for the e2e server despite the plan naming it: pid control wins over plan wording.
## Consequences

S11-04 can land specs against a stack that is already verified up/tear-down-able and chromium is already installed; S11-05 records the ratchet from a command that just ran green (77.4/91/88.1). Costs: the e2e stack duplicates the sidecar lifecycle in bash (the docker restart after seeding is a manual S3-07 — a future compose-based e2e stack could retire it); the detector coverage number depends on a network pip install at run time until S11-02 fixes the image; `test` exits non-zero until S8-12 lands web/e2e/playwright.config.ts, which is honest but means S9-08's green evidence is restart/stop, not test. A media-package flake appeared once under full-suite load (passed twice in isolation, with and without -coverprofile) — recorded for S11-01.
